## 〇、先说一条贯穿三者的共同根源

**设计里有、实现里没有**——三件事各自的直接成因不同，但都落在同一条缝上：

| 设计（图 v0.2 / 规范） | 实现现状 |
|---|---|
| 单元子图两步：**叙事推导**（内部语域，只组织"怎么讲"）→ 卡片写作（客户语域） | **塌成一步**：writer 一次 LLM 调用直接出卡片，没有"讲什么／怎么组织"的环节 |
| 校验三作用域：单元级（causal-link / unit-translation…）、**页级（takeaway / first-visual / one-thesis-per-page）**、册级（branch-cap / set-closure…） | 库里 30 条 `cr-`：**4 条带 pattern 在规则层跑、4 条判官层观察态跑、其余 22 条没有任何执行器**；页级三条判据一条都没物化 |
| 观察态 N 份 → 触发率合格才授予拦截权（规则 4.17 门禁二） | **没有任何地方在计数**（裁决⑨ 已拍"先建计数载体"，未做） |

隐藏档在的时候，这三条缝被"内容本来就发不出去"盖住了：ergonomics 域此前三次真跑全是白卷/failed。
v2.4 把内容放出来，缝就露出来了。**它们不是 v2.4 造成的，是 v2.4 让它们第一次可见。**

## 一、卡片退化：一数一卡、正文与主旨句逐字相同

### 现象（事实）

ergonomics 单元 `verdict=ok`，22 张卡：**22/22 的 `body` 与 `thesis` 逐字相同**，`assertions` **0/22**（一句判断句都没声明）。真句：

> 主旨句：`床面高度在 {lkp-bed-height} 之间，这样你上下床时身体弯折幅度会更小。`
> 正文：`床面高度在 {lkp-bed-height} 之间，这样你上下床时身体弯折幅度会更小。`

### 不是什么（订正一条我自己的错误归因）

初稿写"落点从 3 条变 22 条所以模型开始念数字"，**数字错、归因也站不住**：复算同一份包，ergonomics
23 条落点里 v2.3 口径下只有 6 条会被隐藏，该域**本来就有 17 条可见**。真实情况是**该域此前从未跑出成品**
（8-28 三跑全白卷），22/22 是它第一次有产出就暴露的形态，与"落点变多"没有因果证据。

### 直接原因（前两条是结构事实，第三条是推断）

1. **没有叙事推导这一步**（图 v0.2 §3 的第一步未实装）。"这一域要讲哪几件事、每件事用哪几个落点、
   按什么顺序"没有任何环节负责；user message 里最结构化的东西就是落点清单，模型顺着它一一对应是最省力解。
2. **prompt 里没有"一张卡是什么"的定义**。system 头 = persona 身份 + 七条纪律（数字/占位/语域/禁词/
   断言声明/标注）+ 输出 JSON 格式。**纪律全是"不许怎样"，没有一条说"一张卡要承载什么"**，也没有卡片数量、
   正文与主旨句的关系、必须有推导等要求。
3. （推断，未验证）v2.4 拆掉 `gate-thesis-degraded-anchor` 后主旨句可直接放落点数字，"念数字"这条路阻力更低。

### 目标（规范口径）

- 规则 1.5：专业感六项之首是**推导可见**；规则 1.6：**不许用无背书判断句撑密度**，其 v2.4 形态是"不许不标注就撑密度"。
- 图 v0.2 §4 页级判据 **`one-thesis-per-page`**：一页一个主张。22 张卡各自一个主旨句挂在同一页上，正是它要拦的。
- 图 v0.2 §3：卡片是**叙事推导的产物**，不是落点表的另一种排版。

### 处置选项

| 选项 | 拦得住什么 | 代价 |
|---|---|---|
| A. 加机检 `gate-thesis-body-duplicate`（正文≠主旨句） | 只拦这一种形态 | 模型补一句填充话即可绕过；治标 |
| B. 补叙事推导节点（图 v0.2 §3 第一步） | 治本：先定"讲哪几件事"，卡片按事组织而非按数组织 | 多一次 LLM 调用/单元；prompt 与契约都要设计 |
| C. 物化页级判据（`one-thesis-per-page`/`takeaway`） | 页级结构失控可被拦住 | 需要执行器（当前 22 条 cr- 无执行器同一件事） |

**建议**：B 为主、C 跟上，A 可作为 B 落地前的临时护栏（成本极低，且"正文逐字等于主旨句"没有正当用例）。
**不建议只做 A**——它会把问题从"看得见的退化"变成"看不见的填充"。

## 二、判官灵敏度随卡片数塌陷

### 现象（事实）

同一份文稿、同模型（`report-unit-judge.default`）、同 4 条 observing 判据、`temperature=0`：

- 整单元 **22 张卡 → `observations=0`**；
- 取同一份的**前 6 张再问一次 → 6 条命中**（全是 `cr-anchor-out-of-scope`，逐条指出"落点名只覆盖尺寸，
  卡片却拿它背书人体动作效应"）。
- **没有报错、没有解析失败**（解析失败会 `logger.warning` 并丢弃，日志里没有）。判官就是返回了空数组。

### 直接原因（推断，未验证；证据只到"输入长度是唯一变量"）

- 判官**一次调用送全部卡片**，没有分批；22 张卡 + 4 条判据（每条带反例）在一个 user message 里。
- 判官 prompt 写死了保守偏置：*"没有命中就返回空数组。**宁可漏报也不要凑数**——报错一条的代价高于漏报一条。"*
  长输入 + 保守指令 + 卡片高度同质（22 张同构句式），推测把模型推向了"整体看着没问题"。
- **无法排除**的另一种解释：22 张卡的整体语境让模型认为个别句子没问题（即口径随上下文变化，而非灵敏度衰减）。
  区分这两者需要做"分批 vs 全量"的对照跑，本轮没做。

### 目标（规范口径）

判官层的全部产出是**观察数据**，观察数据的唯一用途是**入册门禁第二道**（规则 4.17：新判据先只记录跑 N 份，
触发率合格才谈拦截权）。裁决⑨ 已拍"先建计数载体，N 与阈值等有数据再定"。

### 为什么这条比它看起来更要紧

**0 命中与"这一份很干净"在数据上不可区分**。计数载体一旦建起来，这类静默 0 会被当作合格样本记进触发率，
于是：该转正的判据看起来不工作（触发率过低）、已转正的判据显得没问题。**统计的可信度在计数开始之前就已经被污染。**
本轮赶在计数载体落地之前撞上，等于先救回了那份统计。

### 处置选项

| 选项 | 说明 |
|---|---|
| A. 分批送审（每批 N 张） | 显然方向。但 N 取多少、分批是否改变判官口径（同一句在 6 张里被判、在 22 张里不被判，哪个是对的？）需要对照数据 |
| B. 先做对照跑 | 同一份文稿按 6/11/22 分批各跑一次，量出灵敏度曲线；这是给 A 定 N 的前提 |
| C. 计数载体带上"送审卡片数"维度 | 与裁决⑨ 一并做：不记这个维度，将来无法回溯解释触发率变化 |

**建议**：B → A → C 顺序，且**与裁决⑨（计数载体）合并为一项**——它们是同一件事的两面。

## 三、`GUIDE_SITE_CHECK` 用在非水电章节语境偏窄

### 背景

v2.3 里"未过门 × PAID × 定位数字"**一律隐藏**（"参考口吻的定位数字不存在"）。v2.4 取消隐藏后，
规则 4.10c 明文把风险交给两件事共同承接：**同页依据标注** + **现场复核话术**，并原文点名
*"安全级话术（§7 锁定文案 `GUIDE_SITE_CHECK` / `DISCLAIM_P1`）本就是为这个场景准备的"*。

### 冲突点

| 事实 | 出处 |
|---|---|
| `GUIDE_SITE_CHECK` 正文写死场景：`请在水电交底当天，携带本清单与施工方逐项现场确认并勾选。` | 注册表（正文已登记） |
| 它的必挂产物原本只有 `art-hydro-checklist`（"清单页头必含"） | 规范 §7 原文 |
| 锁定文案纪律：**只增不改**，正文一经登记不得改；**禁编造正文**（法律性质话术，缺一句只是少说，编一句是替企业作错误承诺） | 注册表三条纪律 |
| 裁决⑮ 已拍：`GUIDE_SITE_CHECK` 推广 → **新增一条 ID**，不得改正文 | 8-29 裁决表 |

于是：报告正文页里出现一个未过门的定位数字（比如某个安装高度），按规则 4.10c 要挂现场复核话术，
但唯一可挂的这条会说"请在水电交底当天携带**本清单**…"——**页面不是清单、场景未必是水电**。

### 当前业务逻辑（实装状态）

- 求值线**派生**必挂：`numberClass=locating` 且 `provenance.annotationRequired` → 该域并入 `GUIDE_SITE_CHECK`；
  成文线照既有链路透传→装配挂页→册级验齐。**机制全通。**
- **但真库里 `number_class=locating` 的参数是 0 条**，所以这条派生至今没触发过，**暂无实际产出影响**。

### 而"0 条 locating"本身是第二个问题（本次顺带查出）

按规范 §2.3 三分法，**定位数字＝施工定位用的坐标/距离/高度**。真库里这些条目却都标成了 `selection`/`analysis`：

`lkp-switch-height`（开关高 1300mm）、`lkp-socket-height-common`（常用插座高）、`lkp-mirror-height`（镜面中心高）、
`lkp-toilet-center-offset`（马桶中线距侧墙）、`lkp-pendant-drop-dining`（餐桌吊灯下沿距桌面）…

即：**分类口径没有落到种子里**。附带两条同源隐患：

- `V2` 迁移的列注释写 `position|selection|analysis`，而契约 schema 与代码判的是 `locating`——**词表两套**，
  且 `verify_seeds.py` **不校验** `number_class` 取值。哪天有人按注释写 `position`，派生必挂会静默失效。
- 分类口径同时决定 §12 那条"prec-schematic 图纸零定位数字"的射程（`cr-no-position-number-on-schematic`）——
  标错的不只是标注挂不挂，还有图纸侧的机检拦不拦。

### 目标

业主拿到一个没有外部依据的安装高度时，必须同时看到两件事：**这个数没有依据**（标注）、**施工前要现场复核**（话术）。
话术的措辞必须与它出现的页面场景相符，且**不得由任何人或 AI 编写**（补录路径只有"从手册原文逐字抄录"或
"起草 + 法务过目"——后者是裁决② 为五条待补录文案开的口子）。

### 待裁（需要用户拍）

1. **是否为"正文里的未过门定位数字"另立一条 ID**（与裁决⑮ 的推广是同一件事，可一并拍）。
   若立：正文走裁决② 的"起草 + 法务过目"路径，落表前状态标"待补录"，机制侧只认 ID 不认正文，可先行挂载。
2. **`number_class` 分类是否重标**（把开关高/插座高/镜面中心高/马桶中线距侧墙一类改为 `locating`）。
   影响面：标注与话术是否挂、图纸侧零定位数字机检的射程。**建议同时给 `verify_seeds` 加取值校验并统一词表。**
