## 一、一句话

- **候选**：许可干净、通道够用、工具链成熟三件同时满足的只有 **SDXL + xinsir ControlNet-Union**（Apache-2.0，depth/mlsd/lineart/seg 一个模型里、多通道同时、diffusers 原生）；画质档更高的 **Qwen-Image 系**（Apache-2.0）要 48 GB 级卡或 fp8；**Z-Image-Turbo + Fun ControlNet**（Apache-2.0，6B，8 步）最快最便宜但多通道同时未写明、ComfyUI 原生支持截至 2025-12 尚在做。**FLUX 全系 dev 权重明确排除生产用途**，出局。
- **GPU 成本**：A10 级按量 7.63–12.71 元/小时，SDXL 一张 1024×768 估 0.02–0.05 元；Qwen-Image 20B 一张估 0.09–1.05 元（看卡）；万相 doodle 文档价 0.14 元/张。函数计算 GPU 按显存 GB·秒计，冷启动 10–30 s。火山 A10/L20 价未查到。
- **跨视角一致性**：查到的手段没有一种能保证"同一张床"；能降漂移的（IP-Adapter、StyleAligned、参考图注意力、分区材质参考）全要**参考图输入**——万相 doodle 没有这个口，只有自部署有。一次多视角生成（SpatialGen）在机制上是唯一"按构造一致"的，但 SD2.1 底、512 分辨率、无 API。
- **触发对照**：失效清单里**只有 B3（透视线被读成斜顶）** 是"要深度通道"的那种，其余构件级四条在万相路径上先改线稿即可；E1（出图变小）自部署按构造解决。

### 3.2 一张 1024×768、30 步的折算（**全部是估算**，没有一条实测）

公开的推理时长只有这几条，其余都是从它们推：
- SDXL 1024×1024 在 A10G：优化后 20 步 **4–6 s**；A100 未优化 50 步 8–10 s（[Baseten 2025-05-18](https://www.baseten.co/blog/sdxl-inference-in-under-2-seconds-the-ultimate-guide-to-stable-diffusion-optimiza/)）。
- Qwen-Image fp8 在 RTX 4090D 24 GB：**71–94 s/张**；加 8 步 Lightning LoRA 34–55 s（按 ComfyUI 官方工作流默认参数，[ComfyUI 文档](https://docs.comfy.org/tutorials/image/qwen/qwen-image)）。
- Z-Image-Turbo 1024×1024 8 步在 RTX 4090：**2.3 s**（[Thunder Compute](https://www.thundercompute.com/blog/z-image-turbo-comfyui)）。
- **A10 / L20 上带 ControlNet 的时长没有任何公开基准**（未查到）。

假设（写死，改哪条重算哪条）：①ControlNet 分支让每步耗时 ×1.3–1.5（无来源，估）；②30 步相对 20 步 ×1.5；③1024×768 相对 1024² ×0.75；④A10 相对 4090 慢 2–3 倍（无来源，估）；⑤ECS/EAS 按满载摊，不算空转；⑥函数计算按"显存 GB×秒"计，vCPU 4 核、内存 16 GB 同时计费。

结论（事实）：A10 级跑 SDXL/Z-Image 一张的算力钱比万相 0.14 元低一个量级——**前提是卡满载**；Qwen-Image 20B 一张与万相同量级到高 7 倍。

### 3.3 冷启动与常驻最低费用

- 函数计算 GPU：端到端冷启动"10~30s"；长时间无调用"所有按量 GPU 实例将被平台释放"，再来就冷启动（[准实时推理场景](https://help.aliyun.com/zh/functioncompute/quasi-real-time-inference-scenarios)）。保温靠浅休眠：GPU 部分按活跃价 11.7%–23%——12 GB Ampere 一小时 **约 1.0–2.0 元**（估算：0.002376 元/s × 11.7%–23% × 3600），一天 24–47 元。最低 GPU 粒度 1 GB 显存。
- EAS："运行中"状态**没有调用也计费**，分钟粒度，无缩到零（[EAS 计费](https://help.aliyun.com/zh/pai/product-overview/billing-of-eas)）→ 最低常驻＝gu30 3661 元/月。
- ECS 按量 A10：9.53 元/h × 24 × 30 ≈ 6,862 元/月（估算）；包月 3203.99（32 核）或 4595.66（8 核）元/月。
- 待裁一件（本文不判）：函数计算 GPU 函数从 imagegen-svc 看是"外部模型 API"形态还是"另起了服务"——《架构对齐》§三把"外部模型 API / GPU 推理"写在同一条伸缩轴上，没说 GPU 推理必须在 worker 进程内。

## 四、跨视角一致性：手段清单

用户 9-04 原话的问题是"同一张床在两张图里不是一张床"。下表每行只写机制、兼容性、自动化、在哪个候选上有、证据；**没有一行能下"一定行"**。判据列写的是将来怎么验，不是本文验过。

| 手段 | 机制 | 与控制通道兼容 | 全自动 | 在哪儿可用 | 证据 | 判据（将来验） |
|---|---|---|---|---|---|---|
| 同 seed 同提示词 | seed 固定初始噪声；控制图变了几何就变 | 是 | 是 | 全部候选 + 万相（`seed` 正式参数） | 9-02 真跑：同 seed 同线稿 100% 相同（《控制图通路调研》§四）；**没有任何资料显示 seed 能跨不同控制图保住物件身份** | 两机位同一件家具的样式/材质差异，人标或 VLM 判 |
| IP-Adapter（风格/材质参考图） | 图像特征进新增 cross-attention，与文本解耦 | **是**：diffusers 文档专节 "Structural control: combine IP-Adapter with ControlNet conditioned on depth maps, edge maps"（[diffusers](https://huggingface.co/docs/diffusers/using-diffusers/ip_adapter)） | 是 | SDXL/SD1.5 原生；FLUX、SD3 有适配；Qwen/Z-Image 未查到 | [h94/IP-Adapter Apache-2.0](https://huggingface.co/h94/IP-Adapter)，每个约 100 MB；InstantStyle 按 block 加权只注入风格不注入布局（同上文档"Style and layout control"） | 第一张图作参考喂第二机位，比"无参考"的样式差异降不降 |
| IP-Adapter 分区遮罩（**材质分层合成**的现成形态） | 每张参考图配一张二值遮罩，只作用于该区域（[diffusers "Masking"](https://huggingface.co/docs/diffusers/using-diffusers/ip_adapter)） | 是（同上） | 是：遮罩可直接用 render3d 的 `mask.png` 按房间/构件切 | SDXL/SD1.5 | 文档示例是双人脸；**材质用途未见样本** | 地面/墙面参考贴图是否按遮罩落到对应区域 |
| StyleAligned（batch 内共享注意力） | 同一 batch 的图在 self-attention 里共享信息，风格对齐 | **是**：官方仓库有 `style_aligned_w_controlnet.ipynb`（SDXL + ControlNet-Depth）（[google/style-aligned](https://github.com/google/style-aligned)） | 是；多机位要**同一 batch 一起出**，显存随视角数涨 | SDXL | Apache-2.0；仓库 **2025-03-03 归档只读**；论文只claim风格，不claim物件身份（[arXiv 2312.02133](https://arxiv.org/abs/2312.02133)） | 一 batch 出三机位，材质色调是否一致 |
| Reference-only（参考图接注意力，无模型） | 把 SD 的注意力层直接连到参考图（[Mikubill #1236](https://github.com/Mikubill/sd-webui-controlnet/discussions/1236)） | 是（本身就是 ControlNet 扩展的一路） | 是 | SD1.5/SDXL（A1111/ComfyUI） | 作者原话："only contains very basic connection codes"；无量化结果 | 同上 |
| 带材质的三维渲染 + 低去噪 img2img（材质由三维场景定，**按构造一致**） | 渲染图当 img2img 起点，denoise 低只换观感不换布局 | 是：img2img + ControlNet（MLSD 0.8–1.0）并用 | 是 | 自部署全部候选；万相 doodle 只吃线稿，**不吃彩色底图**（9-02 对照跑用 `geometry.png` 是让它自己抽线，不是彩色） | 第三方经验值：denoise 0.45–0.55 "keeps the output close"，>0.7 开始漂（[ArchiGen 2026](https://archigenai.com/comfyui-floor-plan-to-3d-render-architects-2026.html)）——**不是论文** | 前提是 render3d 有材质与家具资产，今天没有（9-01"家具 mock 不进生产路径"） |
| 一次多视角生成：SpatialGen（Manycore/酷家乐，3DV 2026） | 输入 3D 语义布局（物件包围盒：中心/尺寸/朝向/类别 + 墙门窗）+ 参考图或文本，联合出多视角 RGB + 坐标图 + 语义图，跨视角/跨模态注意力（[arXiv 2509.14981](https://arxiv.org/html/2509.14981v1)） | **布局本身就是控制**（比 depth/line 更结构化） | 是 | 独立模型，不在上表候选内 | 代码 [MIT](https://github.com/manycore-research/SpatialGen)，底座 **SD2.1**，训练 512×512、8 视角，推理逐视角串行；训练用 64×4090；**推理显存/时长未查到；无 API**；论文自述包围盒"only provide a coarse description ... without pixel-level details"→ 家具样式仍由模型定 | 两机位同一包围盒里的家具是否同一件（论文 claim 一致，未在我们户型上验） |
| MV-Adapter | 多视角适配器，含 ControlNet-scribble 集成 | 是 | 是 | SDXL/SD2.1 | [Apache-2.0](https://huggingface.co/huanngzh/mv-adapter)；**物件级（Objaverse 训练），6 视角 768**，非室内场景（[README](https://github.com/huanngzh/MV-Adapter/blob/main/README.md)） | 不适用室内场景，记一笔 |
| Stable Virtual Camera / HunyuanWorld-Voyager（相机轨迹→一致视频） | 一张图 + 相机路径 → 3D 一致的视频/RGB-D | 输入是**图**不是控制图；只能接在第一张出图之后 | 是 | 独立模型 | SVC **非商用许可**（[HF](https://huggingface.co/stabilityai/stable-virtual-camera)）；Voyager 许可 **MAU > 100 万须申请、排除欧盟/英国/韩国**（[LICENSE](https://huggingface.co/tencent/HunyuanWorld-Voyager/blob/main/LICENSE)），显存未查到 | 第一张图的几何已由控制图锁；后续视角几何由视频模型定——与"几何不由模型决定"冲突，除非逐帧再过尺子 |
| 多图编辑/组图 API：Seedream 4.0 组图、`wan2.6-image` 多参考、Qwen-Image-Edit-2509 "scene + object" | 参考图 + 文本，模型自己保持角色/物件 | Seedream、wan2.6 **无控制通道**（《控制图通路调研》§三）；Qwen-Image-Edit-2509 **开源权重**有原生 depth/edge，可同时进 | 是 | 百炼/方舟 API；Qwen-Image-Edit-2509 自部署 | Seedream `sequential_image_generation=auto`，参考 + 出图 ≤ 15 张，官方 claim 角色一致、风格一致（分镜场景）（[seedream-guide](https://github.com/xujfcn/seedream-guide)、[Seed 博客](https://seed.bytedance.com/en/blog/%E4%B8%8D%E6%AD%A2%E4%BC%9A-%E7%94%BB-%E6%9B%B4%E4%BC%9A-%E6%83%B3-seedream-4-0-%E5%9B%BE%E5%83%8F%E5%88%9B%E4%BD%9C%E6%A8%A1%E5%9E%8B%E6%AD%A3%E5%BC%8F%E5%8F%91%E5%B8%83)）；**室内多机位样本未查到** | 组图三机位，墙位过不过尺子（大概率过不了，因为无控制通道） |
| 场景级材质定义写进提示词 | 文本约束 | 是 | 是 | 全部 + 万相（今天唯一的口） | 9-04 样本："地面材质随房间变（卫生间灰砖）"在文本提示下出现（《失效清单》§一末）；文本能定类别定不了身份 | 同一段材质文本三机位，材质类别一致率 |

事实层面的归纳：能降漂移的手段全部要"参考图输入"或"batch 联合生成"——**万相 doodle 两样都没有**，只有文本与 seed。这是第二形态相对万相唯一在"一致性"上多出来的东西；但没有一种手段声称保住"同一件家具"的身份，SpatialGen 的论文自述也只到包围盒粗粒度。

## 六、建议（执行者判断，不是裁决）

1. **触发前先做便宜的那件**：改线稿（B1/B2/B4）在万相上重跑同一批 16 张，6 张 0.84 元的量级；跑完 B3 还剩多少，才知道深度通道值不值一台 GPU。
2. **若触发，第一个验的候选＝SDXL + xinsir ControlNet-Union**。理由只有三条：depth + mlsd + seg 在一个 2.5 GB、Apache-2.0 的模型里且训练时就学了多通道融合；§四里能用的一致性手段（IP-Adapter、分区遮罩、StyleAligned、Reference-only）全是 SDXL 原生；A10 24 GB 放得下。代价：2024 年的模型，画质档低于 Qwen/Z-Image，社区在往新基座走。
3. **生产候选＝Z-Image-Turbo + Fun-ControlNet-Union-2.1**（阿里 PAI 出、Apache-2.0、8 步、16 GB 级、2026-02 还在更新），但先要**自己验两件没写明的事**：depth + mlsd 能不能一次同时进；VideoX-Fun 之外 ComfyUI/diffusers 能不能跑。验不过就退回 SDXL。
4. **Qwen-Image 系**只在"画质是门禁"时上：单张估 0.09–1.05 元，与万相同量级到高 7 倍，且要 48 GB 卡或 fp8。
5. **第一步验证怎么做**：租 AutoDL 4090（2.19 元/卡时）或 EAS gu30（7.63 元/小时）一台，取失效清单里的**主卧机位**（B3 4/4 出现的那台），depth + line 双通道，1024×768，沿 9-02 三判据跑：线稿转 90°（墙跟不跟）、同 seed 两跑逐像素、三 seed 极差 + 叠红线看图；**再加一条**：B3 斜顶在三跑里出现几次，对照万相同机位 4/4。预算：环境 1–2 h + 跑 <0.5 h → AutoDL 约 **5–7 元**、EAS 约 **15–23 元**（估算，不含对象存储与下载权重的时间）。本机 M1 Pro 16 GB 先不指望：一处资料说 M1/M2 Air 16 GB 跑 SDXL 1024² 30 步 60–90 s/张（[offlinecreator](https://offlinecreator.com/blog/stable-diffusion-mac-apple-silicon-2026)），另一处说 M1 Pro 16 GB "not workable"（[HF 讨论](https://huggingface.co/diffusers/controlnet-canny-sdxl-1.0/discussions/17)），加 ControlNet 后更紧；试一次不通就去租。
6. **一致性**：第一步验证顺手加一跑——第一张出图当 IP-Adapter 参考喂第二机位，看家具样式/地面材质差异降不降；这是今天唯一"零额外模型、零额外许可"的手段。SpatialGen 值得单独立一条调研（酷家乐出品、布局即控制、MIT），但 SD2.1 + 512 + 无 API 三件摆在那儿，不进近期候选。
7. **落地形态**先按 ECS/EAS 常驻算，不按函数计算算：函数计算冷启动 10–30 s 与"GPU 函数算不算另起服务"两件都没定；等出图量有数（《架构对齐》§382 ⑥ 待定项要的正是这个数）再比。
