## 一、文章的方法对着本仓两线

文章七步：找唯一领域专家 → 建数据集（功能×场景×画像）→ 专家做二值 pass/fail 并写批评 → 先修显性错 →
迭代判官并量它与专家的一致率（真阳率、真阴率分开报）→ 按维度做错误分析 → 需要时建专用判官或代码断言。
文章的核心判断＝价值不在判官，在有人认真看了数据；判官是逼人看数据的手段。

## 二、文章方法按本仓规矩改四处

- **"场景库当裁判"要拆开说**：场景库＝考卷（输入集），裁判＝失效清单 + 检测器/判官 + 一致率。考卷不判分。
- **只收真跑样本 + 合成几何照不出问题** → 户型图必须真图（业主已发的、用户真户型、公开房源户型图）；
  家庭画像那一维可以合成（会话侧本来就从面积推）；产物必须过真系统。与文章"只合成输入"同款。
- **数字/几何不由 LLM 决定** → 能 assert 的走代码断言，判官只管代码看不见的失效。与文章第七步同义。
- **品味验证只能是转化信号（规则 4.17）** → 标注只判"错没错"，对照物＝派发数据与户型事实；不判"好不好看"。
  业主挑版这类品味题不当真值，只当信号回证。这是对文章"专家判 pass/fail"的收窄。
- **文章的数不是我们的线**：起步 30、验证最少 60、每类失效约 100、一致率 90% 都是文章的数，只作起步参考（《纪律·阈值有数据才定》）。

AI native 不挡这件事：标注是迭代期人力，不随用户量增长（规则 4.19 判据）；判官生产全自动；样本集是回归集不是验收台。
顺手关《现在在哪儿.md》缺口表两条："改判据没回归立案样本""改 prompt 没跑两侧回归（该禁的／不该塌的）"——样本集就是这两条的结构化拦法。

## 四、看板（执行者判断）

- **边界已裁**：验收台禁（8-27 AI native 裁决禁止项"禁一切验收台"）；只读观测许（规范 §11.4 五项：资产量、核验通过率、needs_review 命中、release diff、种子集回归结果）。
- **数据层已拍未做**：裁决⑨"先建计数载体，N 与阈值有数据再定"，形态＝判据×报告份数×批大小×触发次数，可查询，不建通用平台。看板挂到它上面，不另立。
- **动工理由落在用户身上**：等拍的两件——生图降档的再拍时点、重出上限 K 与预算——都卡在"真实重画率"这个数上，没有计数载体拍不了。
  状态页里的数字（四跑一成、5/6、闭合率 94%、噪声底 0.1718）全是手抄；考卷固定前"成品率跨天不可比"发生过一次。
- **反面**：判官一致率没量之前，看板展示的通过率是未验证判官的数，文章叫它"假信心"。所以看板排在标注与一致率之后。
- **放什么**：业务要的数——出册率/出图率、按户型×功能的通过率、失效模式分布、判官一致率、跨 release 趋势。不放模型自评分，不放 1–5 分
  （文章的警告；规则 4.17"判官与写手同源，自评分必漂"；"有效率是开发给自己打分"那条口径同样管住看板内容）。
- **形态**：先不做网页。计数载体建起来后，考卷跑完自动产出一页汇总进中控仓，替掉状态页里手抄的数字。升网页的触发事件＝出现第二个看的人。
- **命名**："状态页"是本仓纪律术语（《现在在哪儿.md》），新东西不叫状态页。

## 五、建议顺序（执行者判断，非裁决）

1. 三图线失效清单 + 逐张标注：样本＝业主已收真机图 + 三跑记录，标到不再冒新失效模式为止。理由落在业主身上：人脸涂鸦那种图自动放行就直接到业主手里。
   生成成本 0.60 元/张。
2. 异常物件判官（标注集里的 fail 当示范，视觉提案 §10 当判据草稿）→ 对标注集报真阳率、真阴率。
3. 计数载体（裁决⑨）：报告线判据×份数×触发次数；扩到出图线＝每张分数、重出次数、到顶次数，"真实重画率"由此出。
4. 报告线判官一致率：现有考卷跑出的成册逐卡片标 → 过拦（5/5 全拦那类）从此可量。
5. 汇总页：考卷跑完自动出，进中控仓。

物理落点不新开仓：样本集与判官随各生成仓（imagegen / render3d / reportgen 的 `_iteration` 与 tests 已在放真跑样本），计数载体归编排侧（裁决⑨原口径）。
跨线合并成第十二个仓的证据今天没有。
