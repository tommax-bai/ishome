## 〇、怎么读这份清单

三个词贯穿全文，先说清：

| 词 | 意思 |
|---|---|
| **在跑** | 指得出执行它的那一行代码。命中就会拦住产物，业主看不到那份稿子。 |

| **半跑** | 机制在、拦截权不在（判官层观察态），或只在部分条件下才跑。说清哪些条件。 |

## 二、报告线：一份报告从哪几道门过

先说这条线在整个业务里干什么、这些门卡在哪儿——不然下面的规则读不出所以然。

**这条线是付费产物那一半**：业主的户型与需求进来 → 求值线（project-svc，Java）
把所有该算的数算完，产出"落点"（一条落点＝一个有出处的数或区间，例如"主通道净宽下限 900 mm"）
→ 成文线（reportgen，本仓）拿这些数写成人话的章节 → 渲染层把 `{lkp-xxx}` 记号替成真实数字排版成册。
**成文线一个数都不产生**，它只会写 `{lkp-主通道净宽}` 这种记号；数字全由求值线定。

门有四道，按顺序：

```
①数据包体检 → ②写作 →（③单元出口过检·规则层）→（④出口过检·判官层）→ 装配 → ⑤册级校验
                          ↑                        ↑
                      不过就打回重写（最多 2 轮），2 轮还不过 → 整章 failed，整册出不来
```

- **①数据包体检**（`run_package_gate`，`gate.py:889`）：写作之前先验上游给的数据本身有没有毛病，
  省一次 LLM 调用。
- **③规则层**（`run_unit_gate`，`gate.py:951`）：确定性机检，逐字比对，命中即拦。**大头在这里。**
- **④判官层**（`judge.py`）：规则层判不出的语义问题（"这句算不算编造事实"）另一个模型来读。
  **今天四条判据全是观察态，只记录不拦截。**
- **⑤册级校验**（`check_report_book`，`activities.py:383`）：整册结构与跨章问题。

## 二·A 报告线·**在跑**的代码门（43 条中的 40 条）

按"它防的是什么问题"分六组。每组内先列拦得住大问题的。

### A1. 数字纪律——数字不由 LLM 决定（红线，四层堵死的那条）

#### `gate-digit-outside-ref` 正文出现裸数字
- **管什么**：正文里任何一个数字都必须来自求值线，模型不许自己写数。
- **什么时候跑**：写完每一张卡片，扫主旨句+正文（剥掉记号之后的文本）。
- **能过**：`主通道净宽做到 {lkp-corridor-width} mm，推着婴儿车过也不用侧身。`
- **不能过**：`主通道净宽做到 900 mm，推着婴儿车过也不用侧身。`
  ——`900` 是模型自己敲进去的字，没有落点背书；下次求值线改了数，这句话不会跟着改。
- **状态**：**在跑** — `gate.py:1128-1134`

#### `gate-chinese-numeral` 中文数字写的数
- **管什么**：同上一条，堵的是它的绕过形态——模型被禁阿拉伯数字后改写中文数字。
- **什么时候跑**：同上。判据分三种形态：数词+量词、比较词+数词、数词+概数词+单位。
  **列举计数不算**（"四个区域""这三项"可以写）。
- **能过**：`厨房这三项都要一起看。`（数东西，不是报数值）
- **不能过**：`重点照明亮出三到五倍，做菜的台面才看得清。`
  ——"三到五倍"是个没有落点背书的数值，换了汉字不改变它是编的。
- **状态**：**在跑** — `gate.py:1135-1143`

#### `gate-number-ref-unresolved` 引用了不存在的记号
- **管什么**：模型写了一个记号，但数据包里没有这条落点／没有这一项——渲染时会渲不出来。
- **什么时候跑**：单元出口逐卡片（`gate.py:267`），册级再按落点段验一遍（`activities.py:463`）。
- **能过**：`淋浴间宽度不低于 {lkp-shower-size.width} mm。`（数据里确实有 `width` 这一项）
- **不能过**：`淋浴间宽度不低于 {lkp-shower-size-width} mm。`
  ——项要用点号挂在落点后面，写成连字符就变成一条不存在的落点了。打回话会逐字列出它有哪几项。
- **另一种不能过**：`吊柜高度做在 {lkp-wall-cabinet.min} 到 {lkp-wall-cabinet.max} 之间。`
  ——`min`/`max` 是这条落点值的**两端**，不是"项"；拆一端会丢掉另一端。整条写 `{lkp-wall-cabinet}` 就会渲成区间。
- **状态**：**在跑** — `gate.py:267-311`、`activities.py:456-466`

#### `gate-number-ref-undeclared` 正文用了记号却没在 `number_refs` 里声明
- **管什么**：卡片必须自报"我引了哪几条落点"——依据标注、页脚"本页依据"都是按这份声明挂的。
- **能过**：正文写了 `{lkp-corridor-width}`，`number_refs` 里也有 `lkp-corridor-width`。
- **不能过**：正文写了 `{lkp-corridor-width}`，`number_refs` 是空的
  ——这个数就不会有页脚标注，业主看不到它从哪来。
- **状态**：**在跑** — `gate.py:1047-1054`

#### `gate-number-ref-unused` 声明了却没引用（含"假坦白"）
- **管什么**：两种毛病。**（a）粒度写错**：声明的是整条、正文写的是某一项（或反过来）。
  **（b）假坦白**：把有值的落点声明进去，正文却写"这几项目前给不出可靠数值"——把有的数藏起来。
- **能过**：`number_refs=[lkp-shower-size.width]`，正文写 `{lkp-shower-size.width}`。
- **不能过（a）**：`number_refs=[lkp-shower-size]`，正文写 `{lkp-shower-size.width}` ——粒度对不上。
- **不能过（b）**：`number_refs=[五条有值的落点]`，正文写 `这五项目前还给不出可靠数值，等现场量过再说。`
  ——数明明算出来了，却对业主说没有。
- **状态**：**在跑** — `gate.py:1059-1086`

#### `gate-anchors-all-unused` 整章装死
- **管什么**：上面那条的兜底——如果一章**压根不声明任何落点**，上面那条一次都不触发。
  这条判"本域有值的落点，整章正文一条都没露面"。
- **什么时候跑**：一章写完，章级。判据是**零**不是某个比例（"该用掉几条"没有数据，不设阈值）。
- **能过**：软装章 6 张卡里，遮光率、主色上限、配色比例三条落点至少有一条被引用了。
- **不能过**：软装章 6 张卡全写"现在还无法确定具体数值"，而包里给了它遮光率 0.9、主色上限 3、
  配色比例 0.6/0.3/0.1 三条带值落点。（**2026-08-31 真跑立案，就是这一章。**）
- **状态**：**在跑（有条件）** — `gate.py:1250-1267`。本域一条带值落点都没有、或一张卡都没写时不触发。

#### `gate-cost-anchor-unused` 算出来的钱没进正文
- **管什么**：金额是整册里离业主最近的数（"要花多少钱"），不能由写手可选。
  判据：每条 `lkp-cost-*` 落点都至少要被一张卡引用。
- **什么时候跑**：造价章章级（本域有 `lkp-cost-` 开头的落点才触发）。
- **能过**：造价章写了 `硬装总价大致落在 {lkp-cost-hardfit-total} 元这个量级。`
- **不能过**：包里有"水电人工费""硬装总价"两条金额，造价章通篇一个"元"字都没有，
  只讲了各项占比。（**2026-09-08 真跑立案。**）
- **状态**：**在跑（有条件）** — `gate.py:1277-1308`。本域没有 `lkp-cost-*` 落点时不触发。

#### `gate-adjacent-range-refs` 两个区间被接成一个假区间
- **管什么**：**关系不由 LLM 决定**。两个各管一档的区间被连接词拼成一个大区间，
  读者看到四个数却不知道哪档对哪档。
- **什么时候跑**：逐卡片，扫相邻两个记号之间只剩一个连接词（到／至／—／–／～／~）
  且两个记号渲出来**都是两端齐的区间**的情形。两个单值用"从 A 到 B"是正当写法，不拦。
- **能过**：`岩板比瓷砖贵 {lkp-price-ratio-slate} 倍；石英石那一档另算，贵 {lkp-price-ratio-quartz} 倍。`
  ——两个区间各自成句，各说清管哪一档。
- **不能过**：`价差在 {lkp-price-ratio-slate} 倍到 {lkp-price-ratio-quartz} 倍之间。`
  ——渲出来是"1.4–2.0 倍到 1.5–2.5 倍之间"，数据里没有"从这头低端到那头高端"这层关系。
  （**2026-09-07 整册真跑，材质章两张卡。**）
- **状态**：**在跑** — `gate.py:741-782`

### A2. 记号旁边的措辞——写错了话会改掉数的意思

这四条的来路是同一条裁决（2026-08-30）：**在输入的地方给出这个空要填的值的特征，
检测时检测内容合不合这个特征**。值有四种特征，各配一句要求与一道机检：

| 值的特征 | 记号渲出来是 | 句子该怎么写 |
|---|---|---|
| 固定值 | 就那个数 | 前面不许加边界词 |
| 只有下限 | 裸数 | 句子里必须写下限那一族的词（不低于／不少于／至少…） |
| 只有上限 | 裸数 | 句子里必须写上限那一族的词（不超过／最多…） |
| 两端齐的区间 | `900–950` | 不许加单侧边界词 |
| 并列多项 | 渲染层逐项自带说法 | 句子不写 |

#### `gate-bound-word-missing` 该写边界词没写
- **能过**：`主通道净宽不低于 {lkp-corridor-width} mm。`（这条落点数据里只有下限）
- **不能过**：`主通道净宽做到 {lkp-corridor-width} mm。`
  ——渲出来是"做到 900 mm"，读者会以为 900 就是定死的尺寸，而数据说的是"至少 900"。
- **状态**：**在跑** — `gate.py:647-654`

#### `gate-bound-word-direction` 边界词说反了
- **能过**：`全屋色温种类不超过 {lkp-cct-variety-max} 种。`（这条只有上限）
- **不能过**：`全屋色温种类不低于 {lkp-cct-variety-max} 种。`
  ——数据说的是"最多 3 种"，写成"至少 3 种"意思完全反了。
- **状态**：**在跑** — `gate.py:655-660`

#### `gate-bound-word-before-ref` 不该写边界词却写了
- **能过**：`两排柜子之间做在 {lkp-kitchen-aisle} mm 之间。`（数据是两端齐的区间 1100–1200）
- **不能过**：`两排柜子之间不低于 {lkp-kitchen-aisle} mm 之间。`
  ——渲出来是"不低于 1100–1200 mm 之间"，多出来的"不低于"是数据里没有的一层意思。
- **状态**：**在跑** — `gate.py:661-666`

#### `gate-unit-missing` / `gate-unit-after-ref` 单位该写没写／不该写却写了
- **管什么**：单值场合单位由句子写（逐字比对数据里那个单位，写手只是搬运）；
  并列多项场合单位由渲染层逐项带，句子写了就是叠字。
- **能过**：`吊柜离台面留 {lkp-wall-cabinet-gap} mm。`（单值，句子带 `mm`）
- **不能过（缺）**：`吊柜离台面留 {lkp-wall-cabinet-gap}。` ——渲出来是"留 600"，没有单位。
- **不能过（多）**：`淋浴净尺寸做在 {lkp-shower-size} mm。` ——这条并列了宽/深两项，
  渲出来是"900 mm × 1200 mm mm"，末尾多一个 `mm`。
- **状态**：**在跑** — `gate.py:668-686`
- **⚠ 这两条与写作提示词打架，见第六节第 1 条。**

### A3. 语域纪律——业主读得懂、不说行话、不自吹

#### `gate-banned-term` 禁词
- **管什么**：本域禁词表里的词一个都不许出现。词表分五组，**每组给的改法不同**：
  - `weak` 软话（可能／建议考虑／也许／宜／尽量／视情况）→ "这句话要么说定、要么整句删掉"
  - `methodology` 方法论元语言（依据／推导／验收标准／本方案／经严谨／综合考量／作业范围）
    → "报告只讲你家里该是什么样，活怎么干一概不写"
  - `overreach` 越权（保证／确保效果／一定不会／承诺／无风险）
  - `responsibility` 责任话术（责任／免责／由业主自行承担）
  - `domain_extra` / `jargon` 各域行话（延米／净宽／照度…）
- **能过**：`厨房这条动线上，冰箱到水槽这一段最短。`
- **不能过（软话）**：`厨房动线**建议考虑**把冰箱放在水槽这一侧。`
  ——报告不能说完等于没说。换成"或许""大概"一样过不了。
- **不能过（越权）**：`按这个做，**保证**返潮问题不会再出现。`
- **不能过（责任）**：`现场尺寸由业主自行承担核对**责任**。`
- **状态**：**在跑** — `gate.py:1184-1192`；词表 `_common/banned-terms.yaml` + 各域 persona

#### `book-jargon-across-domains` 整册跨域行话
- **管什么**：单元层只拿本域禁词扫本域正文；**业主读的是整本**——灯光域的"照度"写进人体工学章
  一样读不懂。册级把各域行话取并集扫每一页的主旨句、正文与**页脚"本页依据"的落点题名**。
- **什么时候跑**：册级（渲染前），扫全册所有页。
- **能过**：页脚依据一行写"厨房走道最窄处"。
- **不能过**：人体工学页的页脚依据印着"**主通道净宽**""**次通道净宽**"
  ——"净宽"是本域自己的行话，业主读不懂。**这条命中的路是去求值线改题名，成文线不改写。**
  （**2026-09-07 整册真跑立案。**）
- **状态**：**在跑** — `gate.py:843-886`，由 `activities.py:469` 调用

#### `gate-latin-word-leak` 中文正文漏英文词
- **管什么**：中文正文里出现英文词，除单位与专有缩写（LED／TV／low-E 等白名单）外一律打回。
- **能过**：`起居室和卧室的灯，色温要一致。`
- **不能过**：`起居 and 卧室的灯，色温要一致。`（**2026-09-08 灯光章真跑立案。**）

## 五、判官台的失效清单（`ishome-judgebench`）——评测用，**不拦生产**

## 六、发版数据自己的体检（`verify_seeds.py`）——管规则本身，不管报告内容

这一条线的位置：规则写在 YAML 种子里 → `verify_seeds.py` 核验 → `import_seeds.py` 灌库 →
`publish_release.py` 发版 → 随包下发给成文线。**这个脚本守的是"规则本身写得对不对"**，

硬违规（直接失败）逐条：

| 判什么 | 不能过的例子 |
|---|---|
| YAML 解析失败 | — |
| 区间 `min > max` / `effective_from > effective_to` | 单价写着 2026-05 生效、2026-01 失效 |
| 单位不在白名单 | 落点单位写"比率"——**"比率"是量的名字不是记数词**，写手会照抄进正文拼出"0.9 比率"这种业主读不出的东西（2026-08-31 裁决下架，改用 `%`） |
| 单位含本域禁词 | 灯光落点单位写 `×环境照度` ——"照度"是本域禁词，要求写、写了就违规 |
| 数值/公式资产缺 `unit` | 真无量纲要显式写 `dimensionless: true`，不许默认 |
| **条目题名含本域禁词** | 题名写"主通道**净宽**"——页脚"本页依据"印的就是题名（2026-09-07 立案） |

| `max_from` 悬空 | `cr-cct-variety` 指向的 `lkp-cct-variety-max` 在参数表里不存在 |
| `status` 不在闭集 | 写成 `enabled` 这种自造值 |
| `examples` 三件不齐 | 反例只写了 `bad` 没写 `why`/`fixed` |
| `semantic_judge` 判据无 `examples` | 判官无据可依 |
| **判官判据种子不得预置 `status != observing`** | 种子里直接写 `active` ——拦截权只能由观察期数据授予，不能在种子里自己写上（与"种子不得预置 calibrated"同构） |
