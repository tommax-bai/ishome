   源头是《方案/沟通助手架构方案》**§7 那张自标〔草案〕的表**，写代码那一刻**没有任何用户消息**。
2. **没有用户裁决支撑判据内容**。用户当天只拍了两件——"design-svc 拆"与"里程碑引擎用事件驱动"，
   原话一字不多＝`design-svc 拆; v0.3 的做法;`。**拍的是判定机制，不是判据内容。**
3. **机检那条路比确认门早**：`plan-rule-check` 2026-08-22 12:09 由执行者命名（能力概念更早，
   出自用户自己贴进来的 V1 架构文档 03:39），"用户确认门"这个词 15:29 才首现。**先有机检规划，后加人确认门。**

用户 2026-08-22 说的三条，全是"删人审"，**没有一条给替代机制**：

- 15:16:10Z *"那应该是我们系统应该迭代的地方，而不是通过人审，将问题转嫁出去，这没有意义"*

执行者 15:20:04Z 提出替代机制（原话）：

> 3. **校验交给有动机的当事人，做成产品流程**：确认闭环让用户校验自己的事实……
> **你最初定的确认闭环，本质上就是这个原则的第一次应用。**

用户此后**从未逐条回应这四件工具**——下一条消息在 17 秒后，内容是继续陈述"没有人工介入这个概念"。

机检门禁（全自动）+ 用户确认门 + 硬证据机检"。

**一处逻辑反转（本文最值得记的一条）**：执行者 15:13:45Z——即提出替代机制之前 7 分钟、
当时还在为人审辩护——自己写过：

**用户说过的那半，射程是"信息"不是"产物"**：2026-08-22 04:25:38Z

（布局图 / CAD 图纸），**没有任何用户原话支撑**。

**全仓扫描结论**：2026-09-08 之前，没有任何文档／评审／日志把这两条路对撞过一次，

## 四、这五道门从未放行过一次

| 写入方法零生产调用方 | `ProjectAppService.confirmArtifact`（backend `:301-316`）全仓只有两处引用：定义处 + 一个 `@Test`。没有 REST/gRPC/消息/定时任务能到达它 |

c-bff / admin-bff 是 Spring Boot 空壳零控制器，前端 `c-app` / `admin-web` 只有 README 与 package.json。
**业主没有任何按钮可按。** 门本身是真的（`MilestoneCompletionPolicy` 严格判 CONFIRMED、PRESENTED 不算数），
一旦有东西写进去引擎会正常工作——**但今天没有任何东西能写**。

## 五、同类形态扫描：三个仓的同一个洞

**"宣称有门、实际没门"三处**：

| 仓 | 形态 |
|---|---|
| `ishome-aipipe` | `plan-rule-check` / `plan-layout-solve` / `consistency-check` / `compliance-check` 四个 `raise NotImplementedError` |
| `ishome-reportgen` | 发布数据 31 条检查里 **23 条既无 `pattern` 也无 `examples`、其中 21 条 `status: active`**——代码写着"active 命中即违规"＝数据授了拦截权，而 `gate.py:760` 只跑带 pattern 的、`judge.py:102-104` 只跑带 examples 的，**没有任何一层执行它们**。死掉的恰是可数可比的客观项（色温种类超上限、材质种类超上限、过期单价不标取数时间、色彩方案与效果图不一致、人体工学未过项未置顶等） |
| `ishome-imagegen` | 一道被注释宣称存在、实际不存在的"遮罩比对门禁" |

**既遂一件（已经发到业主手里过）**：`ishome-reportgen/src/reportgen_worker/writer.py:476-488` 注释原文——
*"一改：原文写着「可坦白留待现场确认」，真跑成册里四章都把它写成了「等你确认沙发落位」「等你提供物品清单」——
**把我们自己没做完的活说成业主没交作业**。"* 补救只加在提示词里，**机检里没有对应检查**；
而同仓 `gate.py:988` 自己写着教训——*"prompt 里早写着「有值必须照常给出」，这一章照样装死——
**能自动拦住的就别只写在纪律里**"*。那次的教训用在了别的检查上，没用在这条。

**提示词与机检互相打架一处**：`writer.py:416` 教模型"正文里不要再写单位"，
`gate.py:650-654` 的检查却要求单值必须在句子里写单位。git 记录显示提示词那行是旧的、
机检改口径时没回改——**模型同时收到两条相反指令**。

**一个反差值得记**：「数字不由 LLM 决定」这条红线在报告线是**四层结构堵死的**
（引用合法性校验、结构上让 `{lkp-x.min}` 无法表示、干脆不给模型看值、中文数字绕过补丁）；
**同一条红线在获客线只有一句提示词**。这个反差本身就是"该结构堵死的地方漏了"的现成判据。

**正面事实两条**：`ishome-judgebench` 全仓正当，其失效标签闭集里已有 `request-user-measure`

**本次裁决的正确形态，判官台里早就有一条同族的**。`ishome-infra` 零命中。

## 六、防复发：一条可机检的判据

按《纪律·能自动拦住的不写成纪律》——这个项目已有 27 条纪律，再加一条不解决问题。
本次照出的三处同形态给出一条**可做成门禁**的判据：

> **每一条被授予拦截权的检查，必须能指认执行它的那一行代码；指认不出即测试失败。**

射程＝不只拦 `NotImplementedError` 的步骤，还要拦"注册表／发布数据里声明了拦截权、
但代码里没有执行路径"的检查。这是三个仓的同一个洞，**也是「撤掉用户确认门」能不能落地的前提**——
撤掉的若是一道从未打开过的门，换上的又是一道画在纸上的门，等于什么都没做。
