## 一、要回答的问题（一句话）

**有没有一条出图通路，能让"墙在哪儿"由我们给的条件图硬约束住、模型只负责材质和光——而不是模型看一眼参考图然后自己重新决定几何。**

这就是 ControlNet 那类机制干的事：深度／线稿／分割各自作为**独立的条件通道**，在去噪的**每一步**注入结构约束。行话叫"控制图"。本项目架构文档（《方案/架构对齐-设计Agent×技术架构.md》§159）写的就是"底渲**控制图**"，三维底渲那四路（几何／深度／线稿／遮罩）从一开始就是为这种用法造的。

## 二、为什么要问：根因在接口层，不在参数

今天三维写实化走的是网关上的 `realism-pass.default`（物理模型 doubao-seedream-5-0-pro）。它的图生图接口只有一个 `image` 参数——**那是参考图，不是控制图**。参考不是约束：模型看一眼，从噪声重新画一张"像它"的图，每次采样都在重新决定几何。

**五条实测全部指向这一个机制**（不是五个独立的问题）：

| 实测 | 结果 | 说明什么 |
|---|---|---|
| 同一份输入连跑三次 | 一次轮廓分毫不差、一次**凭空多出一整间主卧**、一次把房间**并成大开间** | 几何不受输入约束 |
| `seed` | 同 seed 连跑两次，72.7% 像素差值超 10 级 | 采样过程不可控 |
| `strength` | 三跑对三跑分布重叠，测不出差别 | 保留多少输入不可控 |
| 提示词显式约束（房间数、外轮廓、"线稿是权威"） | 两条改法三连跑极差都没小于噪声底 | 文字压不住采样自由度 |
| 多张条件图一起送（几何＋线稿＋深度…） | 六种组合逐对核过，全部测不出差别 | 多张参考仍然是参考 |

另有一个观察：输出有"裸壳"（无家具、材质近乎不渲）与"富装"（满屋陈设）两种形态随机出现——模型每次在"保真"和"创作"之间随机权衡。

**结论**：这不是"参数没调好"，是**接口层没有暴露结构约束通道**。而且严格说，今天这条通路**违反了本项目红线"几何不由 LLM 决定"**——模型正在决定几何。

**后果**：单张生成不能直接发给业主（会把错的户型发出去）。门禁方案（《方案/挑图与保真度门禁方案.md》v0.2）已立项，形态＝生成→量分→不过线重出——**但它是用概率对抗概率，是接口换掉之前的过渡，不是终态**（方案 §二末条已写成前提，在议未拍）。

## 三、已经确立的事实（不用重做，直接站在上面）

1. **底渲四路出得来、确定性、可当条件图用。** render3d 仓纯库 + CLI 可用；渲两次逐字节相同。`line.png` 是几何事实边，`depth.png` 16-bit 米制，`mask.png` 索引图（0＝背景，索引≡mesh 下标+1），三路是数据不是画面，抗锯齿/降采样会破坏语义，**不许动**。`geometry.png` 是给人看的那一路。
2. **噪声底已量出：0.1718**（同一条件图连跑三次的保真度分数极差）。这是**这把尺子的噪声**，不纯是模型的噪声。
3. **保真度尺子存在但有两条已知限制**（`ishome-render3d/_iteration/run-2026-09-01-condition-matrix/保真度量.py`）：①测得出"墙转向、房间消失"，**测不出整体平移**（等轴测户型图的固有性质）；②**分数混进了"墙线在图上看不看得见"**——几何完全正确的底渲自己量自己只得 0.0607，所以**分数不是保真度百分比、满分远不是 1.0、只能同输出形态横向比**，判断严不严重要看图。
4. **真户型基准数据**（用户裁决）：建筑面积 138 ㎡、得房率 80% → 套内 110.4 ㎡。几何、输入包、四路底渲都在仓里（§七）。
5. **模型选型本来就是架构文档留的待定项**：§382 "剩余待定缩小为 realism-pass 的具体模型选型"。本次调研就是在填这个空。

## 四、调研要交付什么（验收）

一份评估记录（写进 `交接/` 或 `评审/`，格式随本仓惯例），回答：

1. **候选清单与逐个判定**：每个候选，**能不能吃我们的四路底渲当控制图**（不是"能不能上传图"——是深度/线稿/分割能不能作为独立结构通道）。判定必须落在**可观测证据**上（§五），不许写"文档说支持"。
2. **对通过初筛的候选，真跑对比**：同一份基准底渲、同一风格、**连跑 3 次**，给出保真度分数三个值与极差，**并附三张图**。判据：极差明显小于 0.1718、**且看图三跑是同一套房子**（外轮廓、房间数、隔墙位置）。两条都要过。
3. **每个候选的接入代价**：走网关（LiteLLM，逻辑模型名）能不能接；延迟；单张成本；需不需要 GPU 自部署。
4. **一句话建议**：拆分走哪条路——**标明是执行者判断，不是裁决**（《纪律·自己提的要标明不是裁决》）。拆分的三条备选路见 §八。
5. **调用统计**：真发了几次、失败几次、有没有超时未拿到回执的（可能已计费）。

**什么算"没找到"**：所有候选都过不了第 2 条，如实写"当前可达生态里没有"，然后 Loop 就从过渡升为当前唯一形态——这也是有效答案（《纪律·拿不到就说没有，不许填猜的值》）。

## 五、怎么验（方法，不是看文档）

**"支不支持"不能只看没报错。** 本项目踩过两次同一形态的坑：非 OpenAI 标准参数被网关静默丢掉而调用照样成功（图生图退化成文生图、`seed` 发了没用）。判据必须是**因果可观测的**：

- 控制图有没有起作用：**把线稿旋转 90° 再送**，出图的墙体走向应该跟着转。不转，说明它没被当结构条件用（本项目已验证：旋转对照对保真度尺子有效，平移对照无效——别用平移）。
- 可复现性有没有：同 seed 连跑两次，**逐像素比**（降采样到同尺寸后算差值分布），不是看 SHA 也不是看"像不像"。
- 稳定性有没有：连跑 3 次，尺子量三个分数 **+ 看图**。尺子有混淆（§三第 3 条），看图是必需步骤，不是补充。

**候选起点**（这些只是去查的方向，**不是任何一个支持的断言**）：
- 火山方舟（当前网关后端）：Seedream 系列有没有 controlnet / structure 类参数；方舟目录里有没有别的暴露 ControlNet 的模型。
- 国内可达 API：阿里百炼／通义万相（有"线稿生图""局部重绘"类接口，查它们是不是真控制通道）、百度千帆、腾讯混元、智谱 CogView、MiniMax。
- 自部署：SD 1.5 / SDXL / SD3 / Flux + ControlNet（depth / canny / mlsd / seg），diffusers 或 ComfyUI。这条路架构文档 §128 早有预留（imagegen-svc 的伸缩轴＝"外部模型 API / GPU 推理"），**逻辑异质→物理隔离**的红线下它归 imagegen-svc，不另起服务。

**成本自觉**：每次生成约 100–160 秒且要花钱。跑之前想清楚每一次回答什么问题；同一失败不重试超过一次。

## 八、不归这次调研管的（但调研结果会决定它们）

调研只回答"有没有"。拆分走哪条路，等答案出来再拍。三条备选（执行者判断，不是裁决）：

1. **换到真控制图通路**——找到了就走这条，底渲四路直接能用。代价看调研第 3 条。
2. **底渲自己做到接近效果图**（真渲染器 PBR＋光照），模型只做低强度风格化——今天 `strength` 验不出有效，这条在当前接口上也走不通，**换了接口才重新成立**。
3. **分层合成**——几何层确定性渲染，模型只产材质贴图再贴回去。工程量最大，最后考虑。

另两件挂着、与本次无关：`realism-pass` 正式落地的入参形态（倾向一组对象键不是一个 artifact_id，编排侧那行等形态定了再改）；洞口"门还是窗"要上游给字段（今天入户门被画成了带窗台的窗）。
