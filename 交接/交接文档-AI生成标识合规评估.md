## 一、义务清单（逐条带出处）

**法规层（《人工智能生成合成内容标识办法》，网信办等四部门，2025-09-01 施行）**

| # | 义务 | 出处与关键句 |
|---|---|---|
| 1 | **什么算"生成合成内容"**："利用人工智能技术生成、合成的文本、图片、音频、视频、虚拟场景等信息" | 【条文原文】办法第三条 |
| 2 | **图片显式标识**："在图片的适当位置添加显著的提示标识"；深合规定第二十三条明列"**图像生成**、图像增强、图像修复等" | 【条文原文】办法第四条第（三）项；深合规定第十七条第一款、第二十三条 |
| 3 | **文件里要带得走**："提供生成合成内容下载、复制、导出等功能时，应当确保文件中含有满足要求的显式标识"——发文件给业主＝显式标识必须在文件像素里 | 【条文原文】办法第四条第二款 |
| 4 | **隐式标识（对所有生成合成内容强制）**："在生成合成内容的文件元数据中添加隐式标识，包含生成合成内容属性信息、服务提供者名称或者编码、内容编号等"；数字水印是鼓励、元数据是应当 | 【条文原文】办法第五条；【官方解读】CAC 一图读懂 |
| 5 | 传播平台义务（核验元数据、打"疑似"标）落在飞书这类平台，不落在我们 | 【条文原文】办法第六条；主体判定属【推断】 |
| 6 | 用户可申请不加显式标识：须用户协议明确义务，"依法留存提供对象信息等相关日志**不少于六个月**" | 【条文原文】办法第九条 |
| 7 | 不许恶意删标。`watermark:False` 关的是火山**自己可选的**显式水印、官方参数，不构成删标；但**我们关了它又不加自己的**＝交付物零显式标识 | 【条文原文】办法第十条；定性属【推断】 |
| 8 | 算法备案等手续应提供标识材料；罚则走上位法与深合规定 | 【条文原文】办法第十二、十三条 |

**国标层（GB 45438-2025，强制性，2025-09-01 施行）**——取自 CAC 官网"一图读懂"长图逐屏核对
【官方解读】；标准全文 PDF 需在线阅读器，未取到逐条原文，条款号标注不出【查不到】：

- **图片显式标识四件套**：①含"人工智能"/"AI"＋"生成"/"合成"；②位置在**图片的边或角**；
  ③字型清晰可辨；④**文字高度不低于画面最短边长度的 5%**。
  - 对我们的量纲：手账 1584×2816 → 字高 ≥ **79px**；降档 1184×2104 → ≥ 59px。业界普遍没做到
    这个高度（见第五节），但 5% 是国标白纸黑字。
- **文件元数据隐式标识七要素**：生成合成标签、服务提供者名称或编码、**内容制作编号**、预留字段、
  传播者要素等。官方示例＝JPEG 里 XMP 字段 `AIGC`，值为 JSON（`Label` / `ContentProducer` /
  `ProduceID` …）。"应仅保留一份文件元数据隐式标识"。内容水印可选。
- 落地细则在 TC260 六项实践指南（2025-08-28），其中《文件元数据隐式标识 图片文件》专讲图片；
  TC260 官网 PDF 防盗链未取到【查不到，需手动 tc260.org.cn 下载】。第三方实践称图片走 XMP
  （命名空间 `http://www.tc260.org.cn/ns/AIGC/1.0/`）【第三方】。
- `ContentProducer` 27 位编码规则见实践指南，GCmark（gcmark.com）可在线生成【第三方】；
  办法允许"名称**或者**编码"——没编码时填名称是条文允许的【条文原文】。

## 二、射程判定（三类产物逐一）

1. **模型风格图（彩铅/手账写字/将来 realism-pass 效果图）——确定在射程内**：显式＋隐式双份义务。
   三维那条线的逼真效果图混淆风险更高，上线时点必须同套路。
2. **线稿功能说明图（纯代码确定性绘制）——图本身大概率不在射程**【推断，条文无反证】。
   存疑缝：底部判语句子是 LLM 写的（模块注释自认），AI 文本以图片形式呈现，条文答不出算哪类
   【存疑】。房间名是户型事实，不涉。
3. **报告 HTML 嵌生成图**——我们不是"传播平台"【推断】；但①嵌入的生成图文件自带标识即自动合规
   （生成侧烧进文件）；②**报告正文是 LLM 写的＝智能写作类，报告文本自己要显式标识**
   （页首/尾声明），报告线上线前单独落。捎带：飞书 bot 会话是智能对话服务，界面声明可落在
   bot 简介＋欢迎语，低成本。

**实测出的一件此前没人知道的事**：读桶里真产物字节——火山返回的 JPEG 里**已埋一份 C2PA 签名清单**
（APP11/JUMBF 约 140KB，`softwareAgent: Volcengine_Ark_CN`、`model_name: doubao-seedream-5-0-pro`、
火山证书签名），`watermark:False` 关不掉它。**隐式层不是零，是"有火山的 C2PA、没有国标要的 AIGC
元数据字段"**——C2PA 写的提供者是火山不是我们，不能当第五条已履行【实测＋推断】。
plan-brief.png 干净无标（符合其非生成内容身份）。

## 三、渠道会不会破坏标识——查不到，需实测（方法已备好）

飞书文档只说 TIFF/HEIC 转 JPG、10MB 上限；对 JPEG/PNG 是否转码、元数据是否保留只字未提【查不到】。
实测方法（半天）：①API 往返（带 XMP/iTXt 假标识上传→下载→逐字节与逐段比对）；②真机保存件
（业主"保存原图"传回比对——接收端路径可能与 API 不同，两条都测）；③顺手看火山 C2PA 段幸存与否。
**就算飞书剥元数据**：义务在生成侧添加时已履行，平台转码不是我们"恶意删除"【推断】；
显式标识烧进像素，任何转码杀不掉——这正是显式标识必须画进图里的理由。

## 四、两档落地方案（对照表）

代码落点已核对：出图链路 `image_gateway.generate_from_image`（`watermark:False` 在
`imagegen/src/imagegen_worker/image_gateway.py:72`）→ activity 门禁 → `image_store` 落桶；
channel-svc 取桶字节原样传飞书不动字节。imagegen 现无 Pillow 依赖，叠印需新增；render2d 已有
Pillow＋CJK 字体先例。

| 事项 | 最小合规档 | 稳妥档 |
|---|---|---|
| 显式标识 | `watermark:True` 一行用火山角标。零开发；风险：字高是否达 5% 由火山定（查不到）、水印在挑图门禁**之前**进图会扰量测、换厂商即失效 | **自家叠印**：出图→过门禁→右下角"AI生成"（字高≥最短边 5%）→落桶；`watermark` 保持 False 防双水印。代价：imagegen 增 Pillow＋叠印模块＋守卫测试；收益：门禁不受扰、样式统一、厂商无关、转码杀不掉 |
| 隐式标识 | 落桶前写 XMP `AIGC`：`Label:"1"`、`ContentProducer`=名称（条文允许）、`ProduceID`=`{content_sha256}-{template_id}`（**确定性派生，正对"不铸新流水号"纪律**）；火山 C2PA 不动 | 同左＋①GCmark 办 27 位编码；②评估火山 Ark 控制台隐式水印（可代打部分要素，需控制台核对）；③"只留一份"与 C2PA 并存关系向标准原文核对 |
| 线稿批注存疑缝 | 不动（按非生成内容判） | 批注面板尾行小字"批注由 AI 依户型事实生成"——render2d 几行，但默认输出逐字节守卫要改判，明知的破坏性变更 |
| 渠道 | 实测一次落档 | 同左；**不建议**把标识判进渠道出站——标识归生成侧，渠道只负责不改字节（现状已满足） |
| 会话与报告 | 不动 | bot 简介＋欢迎语声明；报告页首尾声明排进报告线上线清单 |
| 三维 realism-pass | — | 上线时点同套路（时点写死＝该 activity 实装时） |
| 不做的风险 | 显式样式赌火山合规；线稿批注裸奔；界面无声明 | 无明显残留；代价三仓各一小刀＋一次编码申请 |
