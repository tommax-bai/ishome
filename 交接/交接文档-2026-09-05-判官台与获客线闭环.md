## 三、迭代机制：反馈→迭代→验证→资产（本轮讨论结论 + 提议）

用户命题：标注完的错误内容，如何用于迭代让它不再错？迭代完怎么 check 好没好？反馈如何记录成后续资产？议出的骨架（**凡提议标【执行者提议·非裁决】**）：

1. **"不再错"的强度分层**（这是机制第一步：每条错先归层）：
   - **代码/确定性错**（几何、闭合、文字叠压、OCR 对不上派发字）→ 改代码 + 把样本变**回归测试** → **真·不再错**（断言永久挡）。闭合 138 就是先例。
   - **模型/语义错**（房间认错、物件、写字）→ 改 prompt/管线 + **回归门禁**（压错误率、挡旧错复发）→ **不是保证，是一道门**。
2. **标注产出两样硬东西**：错误**频次表**（定先修哪个＝错误分析）+ 每条的**正确答案(ground truth)**（用户 c1 批评里就写了"应该是书房…"）。
3. **样本集 = 回归集**（已裁决）：每次改动重跑整集，旧错复发即红。
4. **check 是不是好了**：重跑**同一集** → 目标错消失 + 别处不回归 + 总错率降；先靠人、后靠（对人标校准过的）判官；**防"刷指标"**（看实质不看单一数字——反例＝颜色清洗靠删墙糊房间把闭合率刷到 0.95 却更烂）；阈值现在**不定**（样本少），先用相对趋势（《纪律·阈值有数据才定》）。
5. **反馈资产化五样**：回归集 / 每条正确答案 / 错误 taxonomy+频次 / 批评文本（喂判官 rubric 与 few-shot）/ 人机一致率。
6. **【红线】正确答案只线下用**（度量/few-shot/回归）——**绝不做成运行时的答案表让系统去查**。那一步跨过去＝人预设模板 / 运营编辑后台（红线）。运行时永远从图里自己认（AI native），人工修正只 measure 和教模型、不喂答案。这条一破 AI native 就塌。
7. **判官台＝资产库**，【执行者提议·非裁决】待加三件：①**归类+频次 rollup**（批评滚成错误桶+频次+指向哪个 stage）②**从批评抽结构化正确答案**（如 138 的正确房间表）③**重跑生成→对比正确答案→错误率 harness**。用户命题里"check 怎么做""反馈怎么记录成资产"，答案就落在这三件。
