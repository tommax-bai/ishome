## 五、红线与纪律速查（v2.5 形态，叠加 8-23 红线）

- **数字不由 LLM 决定**；**关系也不由 LLM 决定**（v2.5 新增：落点间耦合不得编造，真实联动在
  `parameters.linked`）；一个占位符＝整条落点；中文数字同样算数。
- **标注必挂**：draft 或已过期落点进正文，同页必须有依据标注——漏标是纪律失效，多标只是页脚多一行。
- **有值必须照发**：坦白只许用于无背书**题目**与真缺口清单；把有值落点说成"给不出"＝隐藏还魂（v2.4 禁）。

## 六、坑单（累积，新 session 逐条当真）

**prompt 工程两条铁律（三次真跑打脸沉淀）**

1. **禁止词面永远不进 prompt，进确定性校验**——把「得一起定」当反例写进指令，4/5 主张逐字照抄了
   禁句本身（与 persona 示范句可抄性同病：模型不区分句子挂的是对钩还是叉）。
2. **措辞会连坐**——"两个尺寸只是恰好都关于床"这半句把"禁编耦合"教成了"别归组"，当场退回
   22/23 一落点一主张。改 prompt 后必须看**两侧**：要禁的禁住了没、不该禁的塌了没。

**上下游同口径**

3. **产物逐字进下一步 prompt 的环节，必须与下一步同一份口径**：推导步没有禁词表，同一个禁词连吃
   三稿（写作步兜不住——下一稿拿到的主张还是那句）。
4. **禁词就藏在落点自己的名字里**（ergonomics 2 条含"净宽"、lighting **7 条**含"照度"）：
   **改说法不改数据**——"照度"在落点名里是准确的，逼它换词面会写成"亮度"，那是两个物理量。
   现形态：撞词的落点在 prompt 里**逐行点名**（数据驱动 banned ∩ name）。

**判官**

5. **判官 0 命中 ≠ 干净**（分批之前的观察数据一律不可信）；**判官输出不确定**（同稿同参两跑

7. **`gate 忽略 status` 是正确实现不是 bug**；**一条 cr- 只能属一层**（规则层恒 active／判官层

**数据与工具**

### 一、点值带容差：删掉那个没有源的 ±0.1（规范 v2.9 规则 4.10e）

**追查出处**（这一步是关键）：`lkp-storage-closed-ratio` 的 `tolerance: 0.1` **自种子首版 `b036bd4`
（系统批量编译六域那一轮）就在**，而该条 `source` 只写"行业通行（二八原则）"——**二八原则给的是
`0.8`，没给 `±0.1`**；同条自己还写着 `source_pending: 无外部标准，属经验条目`。
即：**它是编译时自造的精度声明，没有源。**

用户裁决：**删，不为它扩契约。**

**裁决逻辑**：删的理由不是"没用"，是它**用一个编造的数字，重复表达一件系统已有专门机制表达的事**
——这条是经验条目、没过可核性门，报告本就会给它挂依据标注、把语域限死在"我们建议"（规则 4.10a/4.10c）。
不确定性由标注承担；再加一个自造的 ±，不增加信息，**反而给业主假的精确感**（"80% ± 10%"读起来
像做过测量，实际只是一句行业说法）。

落**规则 4.10e**：禁 `tolerance`/`approx`/"约"一类自造精度声明；真有区间用 `value_kind=range`
且**两端各自有源**、不许由点值折算（折算＝凭空造源里没有的数字，同"数字不由 LLM 决定"）。
核验加拒灌 + 三条回归（含"**有源的真区间照常放行**"——禁的是自造精度声明，不是禁表达区间）。

**连带**：删后**第三种值形态消失**，规则 1.9 的两层模型不必扩。发布跑过，storage 快照内容未变
（该字段本就没投影进快照）——**顺带印证了这个 ±0.1 从来没到过业主眼前**。

**为什么要成条明文而不只删一个数**：知识条目由模型批量编译产出（规则 4.16），"给个数再加个 ±"
是它的自然倾向——没有明文与机检，下一轮编译还会长出来。同规则 4.10b"纪律的形态是机检"。

### 二、"答案是项名"的落点：收回待裁，现状即正确形态

理由两条：①**落点这套机制管的是数字的身份**（来源／取数时间／可核性／语域／标注），对"一个分项的

数据到位后它以**结论**形态出现、由断言预算背书，**不会变成落点**。

### 二、裁决改掉的题目

原形态：渲染层把边界措辞一起渲出来，写手一律不许写边界词。它的问题不在纪律在语法——
**那句中文的语法主干正好落在洞里**。判定材料是十二跑：边界词违规 **9/12 跑**（头号失败形态），

唯一写错的那处正好指出另一件事：走廊照度在数据里是**确定的 100**，模型写了「通行亮度不能低于 ▢」
——**给数据里没有的关系编了一个**。所以"交还给句子"必须同时补上"不该写的地方不许写"。

### 三、落成的形态（四种特征）

| 这个空是什么 | 记号渲出来 | 句子要怎么写 |
|---|---|---|
| **固定值** | `3000 K` | 前面不许加边界词 |
| **只给下限** | `90 Ra`（裸值） | 必须写下限那一族的词 |
| **只给上限** | `3 种`（裸值） | 必须写上限那一族的词 |
| **两端齐的区间** | `900–950 mm` | 不许加单侧边界词 |
| **并列多项** | `宽不低于 800 mm、深不低于 800 mm` | 不写——句子够不着每一项 |

三条要记住的：

1. **分界线只有一条：句子够不够得着。** 一个记号只渲一个值 → 说法归句子；一个记号并列多项
   （淋浴净尺寸的宽/深各只给下限）→ 句子够不着里面每一项 → 说法仍归渲染层。**表格与图框同理**，
   那里"旁边"指列头——**触发条件写死：清单页族落地时同批做那道机检**，不能等它上线再补。
2. **词表是正面清单，不是禁止清单。** 理由是失败方向不对称：正面清单漏一个词只多烧一轮重写，
   禁止清单漏一个词**缺陷就进成品**（当日上午那句叠字正是后者）。这条比"哪个词表更全"重要得多。
3. **分项落点的整条引用与按项引用是两个不同的空**，特征分开说——只说前者，模型按项引用时会
   照着一句对不上的话写，然后被打回，而重写只有两轮。

判据按"哪里不对"分三条：该写没写／方向写反／不该写却写了。三种的改法不同，合成一条等于给模型
一句它得自己拆开的话。

**驳回成立**：出册率是业务要的数，有效率是开发给自己的改动打分，后者不构成产品需求。

两条理由（第一条是用户点的，第二条是落档时补的连带）：**①判和写不能同层**，判据一旦给出该写什么，
出文的责任就散成两处；**②替代说法固定在 release 数据里，每份报告都说同一个词＝人预设模板**，
撞 AI native 红线。现形态：打回只说"这个词不行"，**换成什么由写手自己判断**；
它判不出来时的后续路径写死＝**把它已经试过的写法告诉它**（§一），不是给它答案。
