## 〇、一句话版

**成文线产出到 `pages` 就停了——项目至今没有任何东西把它变成人能读的报告，也没有任何人（包括用户）见过一份报告长什么样。** 本线要做的：一个**确定性、零 LLM** 的渲染层，把「pages + 报告数据包」变成一份能打开阅读的 HTML 册子。做完的验收：**打开一个文件，读到人体工学章的卡片、页脚的依据标注、锁定文案正文——第一份人能看到的报告。**

为什么现在做（三个都成立）：

1. **存量工作不可验证**：到今天所有质量判断都是从违规清单和 JSON 里推的，没人读过成品；
2. **两条已实装的纪律在纸面上不存在**：依据标注（规则 4.10c 标注必挂）与锁定文案（规则 2.4 gen-locked）的正文都约定"渲染层按 ID/结构化数据出"——渲染层不存在，这两样在业主面前就不存在；
3. **行为信号闭环的前提**：规则 4.17 的一切转正信号来自业主对内容的反应，前提是内容能被看到。

## 二、裁决与默认（接手第一件事：请用户拍板落档）

**待拍板 · 渲染层落仓**。推荐默认：**独立仓 `ishome-reportrender`，先以纯库 + CLI 形态存在，不起服务**。

两条既有裁决在此有张力，如实摆出：

- 支持独立仓：**"逻辑异质→物理隔离，不采信模块边界替代物理隔离"**（用户裁决，chat/project 与绘图三仓拆分同源）——渲染是确定性代码，成文是 LLM；更硬的一条：**锁定文案正文必须对 LLM 侧结构性不可见**（"写作层结构性拿不到"是现有保证的原话），正文数据放进 reportgen 仓，这道结构保证就退化成了口头纪律。
- 反对成服务：规范 §13.6 服务存在性判据（无独立伸缩轴/故障域→不成服务）。
- **化解**：独立仓 ≠ 独立服务。仓管物理隔离，服务等"报告一键触发"接编排时再起 worker——两条裁决都不违反。

其余默认（拍落仓时一并确认）：模块名 `reportrender`；输出**单册自包含 HTML**（可打印 A4；PDF 走浏览器打印，后续项）；将来接编排的 activity 注册名 `report-book-render`、队列 `reportrender-activities`（届时走 contracts PR，注册表只增不改）。

## 三、渲染层的纪律（红线，违反即返工）

1. **零 LLM**：整个渲染层没有一次模型调用；它是 gen-locked 的执行者，不是生成者。
2. **锁定文案禁编造、禁拼接**：正文只按 ID 从数据取，逐字输出；**"把免责接到句子后面"这种拼接也禁止**（注册表纪律原文）。缺正文（待补录）= 该句缺席，**缺是少说，编是替企业作错误承诺**。
3. **数字原样输出，禁换算折算**：`{lkp-*}` 占位符替换为落点值 + 单位，**一个占位符=整条落点**（区间渲染成区间）；mm 不折算成 m、0.03 不擅自变 3%——换算=渲染层自己造数字。百分比等表示问题遇到即上报待裁，不猜。
4. **fail loud**：占位符找不到落点、值形态不认识（如分档映射内联）→ 渲染失败并报明细，**不空替、不静默跳过**（过拦与漏拦同样是失效，静默丢内容是漏的一种）。
5. **不重判**：pages 已过册级校验（标注齐、锁定文案齐由 `report-book-check` 保证），渲染层只执行不复核——与"成文线不重判求值线"同一哲学。
6. **`lkp-` 标识名禁入输出**（客户语域禁内部编号）：依据标注展示用**落点名称**（从数据包 anchors 按 lkp_id join 出 name），lkp_id 本身绝不出现在 HTML 里。
7. **匿名**：输入即匿名（数据包结构性无用户标识），渲染层不得添加任何来源之外的信息。

## 五、坑（给接手 session，均有出处）

1. **`provenance_notes` 里只有 lkp_id 没有名称**——展示名必须从数据包 join，直接打印 lkp_id 即违规（红线 6）。若嫌 join 烦，正路是给 `ProvenanceNote` 加 name 字段（契约只增不删，两侧同步），不是打印 id。
2. **值是异构 map**（`{min,max}`/`{v}`/分档键/嵌套），形态清单见 backend `RulebookEvaluator` 与真跑数据。**首版只做三形态，其余 fail loud**——分档映射（如置信→宽度）的呈现是设计题不是替换题，别顺手内联。
3. **`withheldAnchors` 恒空**（v2.4 作废字段），渲染层不消费；生产方若发 `WITHHELD` 档位，reportgen 侧整包解析失败是**故意的严**，渲染层同理不做宽容解析。
4. **DISCLAIM_P1 属图框**：prec-schematic 图纸的免责由绘图服务挂（注册表"运行时消费口径"表），本线只管**报告册页面**上按 `locked_text_ids` 出现的文案，别去实现图框。
5. **中控仓不放代码**，渲染代码只进新仓；本文所在仓只收文档。
6. 本机环境坑（uv 用阿里镜像、代理 7890、gh 偶发 EOF 重试）见《交接/落地日志-2026-08-23.md》§四；建 GitHub 私有仓用 `gh`（账号 tommax-bai），SSH 走 443 改写见同文。
7. **push 时机由用户定**；提交信息中文、Conventional Commits。
8. 渲染样式别过度设计：本线验收是"能读"，不是"好看"——先让 22 张卡、标注、文案全部如实出现在纸面上，美化等页型库（pt-）落地再说。

## 追记二（2026-08-29 晚，执行者 Claude）：落仓判据订正——锁定文案不可见性与仓边界无关

**结论不变**（独立仓、纯库 + CLI、不成服务），订正的是 §二 与追记一里的一条加固理由。用户追问"独立仓为什么会不成服务"，答疑时核了注册表与成文仓原文，发现 §二"更硬的一条：锁定文案正文必须对 LLM 侧结构性不可见，正文进 reportgen 仓则保证退化成口头纪律"**不成立**，追记一"物理隔离的真正承重点是锁定文案正文"随之作废：

1. 注册表原话的机制是**成文侧数据模型不含锁定文案位**（reportgen `Card` 上无此字段）——承重件是载荷形状，形状本身就定义在 reportgen 仓内部，仓边界从来不是这道保证的执行者；
2. reportgen 依赖 contracts 走 `subdirectory = "gen/python"` 的 git dep，**注册表数据文件本就在其 import 面之外**——正文即便落 contracts，只要不编进生成代码，写作层照样够不着，与渲染代码在哪个仓无关。

**判据收口为物理隔离一条**（确定性渲染 vs LLM 成文，逻辑异质，与绘图三仓、chat/project 同源），单独足以支撑独立仓；不成服务照旧走规范 §13.6 服务存在性判据（同判据先例：清单族规则求值引擎连独立仓都不给，落 project-svc 模块）。《落地假设与拍板清单.md》§〇 该条已内嵌同款订正、《仓库拓扑.md》删去该半句（活文档就地改）。**答疑中确认的一条事实顺记**：仓与服务在本项目本就不一一对应——backend 一仓八服务、aipipe 一仓三服务，contracts/infra 独立仓零服务；CLAUDE.md 红线速查"独立仓+独立服务"括注已补"两判据分列"说明。

**连带提醒建仓事项**：`locked_texts.json` 落点（§四"锁定文案数据化与挂载"）设计时须保持上述第 2 条成立——数据文件放 contracts 注册表目录、**不编进 `gen/python`**，渲染层以数据文件形态消费（git dep 拉全仓可达，或另行显式取用），写作层依赖面不扩。把它编进生成代码 = 亲手把"结构性拿不到"改成"结构性拿得到"。
