## 一、目标与这条路的三段

目标（用户 2026-08-30 裁决，未变）：**真人发一张户型图，收到一条链接，点开是关于他自己家的报告。**

| 段 | 干什么 | 状态 |
|---|---|---|
| **入口** | 图从会话进来、落私有桶、派发解析 | **零**——入口那一半见《交接文档-用户发图到拿到报告.md》 |
| **中间** | 把数据写成一份报告（成文→装配→册检→出册） | 能写出来，成品率见下 |
| **出口** | 册进私有桶、签名链接送回业主 | **做完了**，真跑过、业主点得开 |

## 二、为什么下一件是量整册，不是接入口

1. 中间那段的成品率，2026-08-30 一晚从 **1/12 提到 5/6**（同一份输入重复跑六次，五次出得来册）；
2. **但那个 5/6 是单章的**（只跑 lighting 一章），而报告是六章的，**六章都得成整册才成**；
3. 单章 5/6 的话六章约三成；而已知其他章更差（budget 2026-08-29 才第一次过检，
   ergonomics 记录在案是"收敛率低"），真实数字大概更低；
4. **这个数从来没人量过——我们一次多域整册都没跑过**；
5. 所以先量它：**若整册只有三成成，现在接入口等于把失败直接交给第一批真人**。

判读之后两条路都写死，不留开放结尾：

- **整册出得来** → 下一件是**接上传入口**（《交接文档-用户发图到拿到报告.md》第二节五段）；
- **整册出不来** → 看 `failed_domains` 是哪几章、`failed_units[].violations` 是哪几条，
  **按章修**，修完**再量一次整册**（不是量单章——单章数已经证明会误导）。

## 三、判读标准（先定好再跑，免得看见结果再找说法）

一次派发，看返回体三个字段：

| 字段 | 含义 |
|---|---|
| `verdict` | `ok` = 整册成；`failed` = 没成 |
| `book_key` | 有值 = 册真的进了私有桶（全链路，不只是成文） |
| `failed_domains` / `failed_units[].violations` | 没成时，哪几章、栽在哪条判据 |

**跑一次即可**（用户裁决）。一次的结果不是概率，是"这件事此刻做不做得到"——够决定下一步了。
若一次就成，可再按同一条命令补跑两三次看稳不稳；若一次不成，失败原因本身就是下一件活，
不需要重复跑来确认。

## 六、接手要知道的机制（2026-08-30 ~ 31 新增，全部已落《落地假设与拍板清单》）

- **不为测量而测量**：一件工程要做，理由必须落在"用户拿不到东西"或"拿到的东西不对"上；
  "我想知道上一个改动有没有用"不是理由。
- **判据只判不写**：打回只说"这个词不行"，**不给替代词**——替代说法固定进数据＝人预设模板。
- **打回带历史，射程＝所有裁判场**：最新一稿带全文；更早各轮只带原因不带原稿；
  同一条判据跨轮再犯的标在当条违规后面，**按判据归并不按卡片**。写作步与推导步同形。
- **prompt 自己不许写它禁的词**：两步各有一条守卫测试，剔除禁词表本身那一处后再出现任何禁词即失败。
  题名撞词走**逐行点名**（数据驱动），那不违铁律一——不是塞新词面，是给已在输入里的词贴标签。
- **指令必须与它描述的输入对得上**：本轮三次栽在这一族（纪律举例写了禁词、纪律引用了不存在的
  档名、打回名单与纪律给的名单不是同一份）。改 prompt 时**两侧都要看**。

## 八、坑（逐条当真）

1. **跨仓集成只有跑全链才暴露**：两侧测试各自全绿、整包却被对方 `extra="forbid"` 拒收——
   这事 2026-08-30 一天发生了两次（`triggeredRulesByDomain`、`bannedTermGroupsByDomain`），
   第二次是**成文已经过了、死在出册**。生产侧加顶层字段，消费侧必须同批认下。
2. **多 session 共用工作区**：同一批仓上可能有别的 session 在改，`git add -A` 会带走在途改动。
   **一律显式 add 路径。**
3. **重启共用服务前先看有没有在途工作流**（`temporal workflow list --query 'ExecutionStatus="Running"'`）。
4. **gradlew 要 JDK 21**：`export JAVA_HOME=/opt/homebrew/opt/openjdk@21`，否则 bootRun 起不来。
5. **改 prompt 后必须看两侧**：要禁的禁住了没、不该禁的塌了没。本轮把语域档写得更具体，
   结果六跑里三跑模型开始把落点题名当断言题目声明——**一次纯粹由措辞引发的回归**。
6. **push 时机由用户定**，本地提交领先远端是常态。当前五仓有未推提交（含别的 session 的）。
