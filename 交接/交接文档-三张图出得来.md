## 二、这一段的分工，三条线各归各位

**几何 / 母版 / 说明图＝确定性；风格图画面＝生成式；说明与文案＝语言模型。** 分界不是风格偏好，
是三条已定原则的同一次应用：

- **几何不由 LLM 决定**——墙、洞、边界从像素算；
- **数字不由 LLM 决定**——面积占比、开口数、人数、得房率都由代码算；
- **字要落得准就不能交给图像模型**——房间名、批注、标题全由确定性排版层叠。

由此得到一条可复用的判据：**这件事有没有一把尺子？有，就归代码；没有，才归模型。**
批注"这间房怎么用"没有尺子，归模型；"这间房占多少面积"有尺子，归代码。

## 三、母版：几何唯一源，它自己会拦自己

母版＝几何 → **母版 PNG + 墙体图层 + 房间遮罩索引图 + 房间锚点**。纯库 + CLI（同渲染层先例），
接进 activity 的时点写死＝派发链路接通时。

三处画法是判断不是默认值：

1. **母版上不写字**。房间名归后面那一步，母版只把"字该落在哪儿"（锚点）算出来交出去——
   母版因此**不依赖任何字体**，本机与服务器画出来是同一张图；
2. **内墙的洞画成门（断开），外墙的洞画成窗（墙不断，墙内留细缝）**。产出侧只分内外墙不分门窗，
   而这一分正好够用：首版全按断开画，92㎡ 样例的外墙被九个飘窗啃成碎渣。
   **已知代价＝入户门开在外墙上会被画成窗**，一处换一圈闭合外墙；消它的时点写死＝
   产出侧补上门窗识别那一批；
3. **外圈闭合率是母版自己的自证数**，低于 0.90 整张不出。

**它上线当天就拦下了自己**：真实样例外轮廓只有 **64%** 被墙盖住。这不是画法问题——

## 四、几何被消费方逼出来的两处补漏

**"先有消费方再有契约"这条纪律，这次真的换来了东西。** 几何自己跑过三次、自证覆盖率 97.3%，
两处硬伤都没露出来；**一开始画母版，第一次就撞上**：

### 缺一：产物没带自己的参照系

x 按图宽归一、y 按图高归一，**两个方向除的不是同一个数**。消费方不知道原图多宽多高，
一张长方形的户型会被画成正方形。补 `frameWidthPx`/`frameHeightPx`，与比例同进同出。

不违反"产物里不许出现绝对尺寸"：那条禁的是没有比例尺就冒出来的真实世界尺寸，
**参照系是像素、是这套比例的分母**，两回事（两条守卫测试并列，各写明射程）。

### 缺二：没有外轮廓，外圈闭合率只有 64%

两个成因，都不是"再调阈值"能补的：

- **网格投票表达不了台阶**：飘窗那段墙往外折一个台阶，整段被读成"洞"，台阶本身那截短墙又短到
  投不出线；
- **飘窗那几条边一个墙像素都没有**：楼书图上飘窗画的是两条细窗线，被"去家具线"那一步的开运算
  连同尺寸线一起抹光了。

改法是另给一条来路：**`is_inside`（从图边向内漫灌灌不到的地方）的边界就是外墙外沿**，
它本来就是从像素里算的——"墙在哪儿全部从像素里算"没有松动。沿边界扫连续段、往里量墙带厚度，
按墙心线给出，分列 `outline` 字段（洞只挂在 `walls` 上，外轮廓不产生洞；重合的段不去重——
**去重要判"这两段是不是同一道墙"，那是又一个会错的判断，而重画一遍没有代价**）。

**量不到墙的段照出，厚度借其他外墙的中位数**：边界在那儿是事实，墙像素不在是画法。
丢掉它们等于把户型画成漏风的，而它们是不是实墙，洞的清单已经如实标着。

补完：**64% → 94%**。

路上还修了一个同族的坑：量墙厚问原掩膜，会顺着与它相交的那条竖墙一路走到底，量出过
**"厚 242px 的外墙"**。改问按轴向分开的墙体图——《户型图解析与出图启动》追记九判洞时踩过同一个坑。

## 五、风格图：房间表非填不可，网关必查回执

母版 + 房间表 + 模板 → 一张图形层。**模板本体只有风格、构图、禁令三段（数据，`templates/*.json`）**，
户型专属那部分是槽位由母版填。第三张（彩铅）**只加了一份模板数据，一行代码没动**——
"模板与实例分开"第一次真的兑现。

两处是真跑逼出来的：

1. **房间表非填不可**。首跑把母版原样丢给模型、不给房间表，**厨房跑到了次卧的位置**。
   母版上不写字是刻意的，模型只能靠家具猜功能，猜错是必然不是偶然。房间方位由母版的锚点
   算成九档（upper-left / middle-center …），**算出来的不是看图说的**。补上之后九间房功能全对；
2. **网关必查回执里的 `input_images`**。图生图的 `image`/`size`/`watermark` 都不是 OpenAI 标准参数，
   网关一开 `drop_params` 就丢掉，**调用照样成功、出来的图与母版无关**——这是这条线上最贵的
   一种失败（静默退化成文生图）。不是 1 就整张失败。

**"不要出任何文字"这条模型听得进去**，两个模板各跑都是零字——文字层与图形层分离那条口径
因此站得住，不用赌。

### 几何跟随度：只看召回那一半

| | 母版墙被盖住 | 生成墙落在母版上 |
|---|---|---|
| 情绪图 | 89% | 84% |
| 彩铅 | **99%** | 72% |

彩铅那 72% **不是画歪了，是画风把这个数带偏了**：彩铅家具线多、深色像素多，"不在母版墙上的深色"
自然多。**跟随度用召回那一半，精确率不跨画风比。** 门槛与"不达标重生成"那道门禁**还没做**，
时点＝三张图齐了要挑一张出去的时候。

## 六、说明与文案：一条要引得到事实，一条不要求

用户在过程中纠正过一次口径，值得逐字记：功能说明图**要走模型**——

> *"不走模型的话，我们怎么生成说明的内容呢？"*

拆开就清楚了：**说明的内容**是语义判断只能模型产；**说明的画法**是坐标必须确定性画。
执行者上一版把两件事说成一件，被用户当场纠正。

### 批注：空间推理背书通道第一次实装

模型拿**带 id 的户型事实**去推理，每句必须声明引用了哪几条；机检两条——引用的 id 必须存在、
一条都没引的直接打回。**不是禁止它编，是编了引不到**。

三处是结构不是纪律：**不把图递给它**（递图＝给它第二个可以照着编的来源）、**产事实与用事实
分层互不可见**（产的那侧够不到网关、用的那侧够不到几何）、**句子归模型判据归代码**。

真跑：**过检 5 条、打回 0 条**。

**如实记一条机检覆盖不到的**：事实说"外墙上有 2 处开口"，模型写成"有两扇窗"——开口→窗是一次
推理，机检只保证依据存在、不保证推理对。卧室外墙开口确实是窗，**但玄关那处是入户门**，
同样写法就会错。与"洞不分门窗"同源，消它的时点＝产出侧补门窗识别那一批。

### 事实：只出站得住的那几类

从几何算：户型清单、面宽进深比、每间的面积占比与长宽比、每间外墙上有几处开口。**只从几何产、
不从模型产**——这批的定义就是"读者看图即可自验"的那种。

**"哪两间是通的"那一类撤下了**（立案不是遗漏）：首个真实样例产出过「卫生间与小孩房直接相通」
「卫生间与餐厅直接相通」两条不成立的关系，而真正的枢纽客厅只连出一条。成因不是探测距离，
是**走廊不是房间**——LDK 开阔区被分给客厅和餐厅，门开在走廊上，探两侧就探到了隔壁。
**一条错的事实被句子引用比没有它更糟**：机检只保证 id 存在、不保证事实本身对，
所以事实这一层的门槛只能更高。恢复时点写死＝房间边界在开阔处稳定之后。

### 文案：用户裁决不走强制引用

> *"不用跟批注一样，这里我们直接推导就可以了，这个是一个获客的工具，它不是严谨的报告数据，
> 我们的东西只要在合理范围内就可以接受。"*

执行者收窄两条：**数字必须在事实清单里出现过**（"数字不由 LLM 决定"是全项目红线不是报告域专有，
且数字串可枚举、机检可判）、禁自造精度声明与承诺。**事实清单照样递过去当素材**——
不给素材的"直接推导"就是编。

**判据分界一句话**：看这句话是不是要被人当依据用。报告里的话业主会照着买东西、照着画线；
获客图上的话是让他愿意点开。

## 七、叠字：放不下就不叠

标题、情绪总结、三块贴士叠到风格图的留白带上。**叠字前先量版面，放不下整张失败**——
失败形态是"重生成一次"，不是"字压在他家客厅上"。

量的是**最长一段连续空白**而不是空白占比：占比六成完全可能是"上三成空、中间画面、下三成空"，
两段都塞不下一行标题。

两个判据都是量出来的不是拍的：

- **空白容差 60**：同一张真跑图上，留白带行跨度中位 **20**（纸纹颗粒）、画面带中位 **237**，
  40/60/80 给出完全相同的判定，说明落在分离带上。**首版取 12，卡在纸纹上，把留了白的图判成没留**；
- **一行算空白要同时"跨度小"且"跟纸一样亮"**：只看跨度会把**一整行纯黑**当成空白（跨度也是 0），
  单测造图时一条贯穿全宽的黑线就把首版骗过去了。纸色不写死，取四角小块的中位灰。

**门禁真拦过一次**：模板向模型要顶部 16% 留白，它给到 245px（约要求的**三分之二**），差 35px。
按实测把要求提到 24%/28% 后拿到 373px，叠上了。**要求要按实测放大，不能照着最终需要的尺寸去要。**

## 八、会话侧：从"问齐了再做"改成"先做出来再让他改"

同日用户连着纠正三次，**每一次都是同一种病——系统在问它自己能算或能推的东西**：

| 用户看到的 | 根因 | 改法 |
|---|---|---|
| 连问三轮"请提供一个实测尺寸，您手边有卷尺吗" | 比例锚点被写成必答题，缺口判定只看事实在不在、不看用户说过什么 | 比例锚点退出缺口；尺寸由四级标定自己算 |
| 传完图还问"您家在哪个小区？几室几厅？" | 缺口口径是解析与几何存在之前的措辞；且"他传了图"等模型去抽，有一轮延迟 | 缺口改成"请他发图"并写死不问小区名/几室几厅/面积以外的数；**收到图片入站由代码直接记事实**——代码知道的事不问模型 |
| 问完人数与诉求，下一条却说"我按 4 个人来安排，不说也没关系" | 缺口清空后上下文没东西了，而回复规则还写着"针对缺口提问"，它自己编了一个要问的 | 缺口为空时**明说"这一轮不要再向他要任何信息"** |

### 现形态（用户裁决 2026-08-31）

> *"用户需要给我们东西只有两个，在最开始的时候，第一个是面积，第二个是户型图。"*

面积与户型图之外一概推断：**人数、得房率、装修倾向、年龄由代码从面积算**，不经模型。
锚点是用户给的那一个——138㎡ → 4~5 人、按 4 人做（每人 34 ㎡）、得房率 80%、年龄 30。
装修倾向按面积分四档，**面积决定的是"先要解决什么"不是审美偏好**，每档带一句理由，
因为那句话要摊开给业主看。

两样齐了**不再出确认清单**，改为把假设摊开说一次并给改的入口——**给了就用、不给就算、不追问**。
只说一次：每轮再说一遍就从"告知"变成"催问"。确认闭环那套机件没删，**时点挪到真有产出可确认时**。

**得房率对业主说 80%，进几何与报告数字的计算仍取区间下限**——8-30 那条"取大则业主按报告买的
柜子装不进"的理由未被推翻。一个沟通口径一个计算口径。**真要统一由用户拍。**

### 另外两处也已上服务器

- **回话按思维停顿分条**（用户裁决：写的模型自己标断点，不另起切分模型——思维停顿是写的时候
  产生的，不是文本的属性）。条与条之间按上一条长度歇 0.4~1.5 秒；
- **不把内部字段名递给模型**：首版把 `floorplan/source = upload_pending（observed）` 喂进上下文，
  模型原样转述给业主"（来源：upload_pending）"。改为客户语域渲染——**它看不见就说不出**。

## 九、坑单（都是这一段真踩的）

1. **回复被解析器整轮丢光**。模型照做了分条（回了数组）**但键名仍写 `reply` 而不是 `replies`**，
   首版只认两种形态，那一种两边都不沾，业主收到兜底话。**丢掉它的是解析器不是模型的输出**——
   键名与形态都要收宽（两个键 × 数组/单串）；
2. **比这更该修的是它不响亮**：那次日志里只有一行"reply sent"，没有任何异常。现在一条回复都没
   解析出来时把模型原文记进日志；
3. **纪律禁不住的用结构禁**。提示词写着"一次只问一件事"，真机两跑都问三件；改成**一次只把最要紧
   的那一个缺口递给它**，三跑问号 2/0/1。同"推导步看不见落点的值所以产不出数字"；
4. **服务器上一个中文字体都没有**（`fc-list :lang=zh` 为空）。已装 `google-noto-sans-cjk-ttc-fonts`，
   路径 `/usr/share/fonts/google-noto-cjk/NotoSansCJK-Regular.ttc`。**字体找不到要整张不出、
   绝不画豆腐块**——本机有服务器没有，于是本机好看、部上去全是方块，而它**看起来是画出来了**；
5. **新逻辑模型名的第一次真跑另起临时端口**（`infra/litellm/run-dev.sh 4001`），跑完停掉，
   常驻的 4000 全程不动。本轮加了两个逻辑名，两次都这么跑的；
6. **aipipe 的 contracts 依赖锁在 v0.2.0**，还没有 `objectKey` 字段——抬版本的时点＝
   做"会话收到图、上报业务侧"那一段；
7. **消费侧 `extra="forbid"` 会拦下产出侧新加的字段**，本轮拦了两次（几何的 `outline`、洞的
   `connects`）。**那正是它的用处**：两侧逐字副本对不上就是接不上头。

## 十、跑法（照抄）

**三张图整条链，本地就能跑完，不需要起任何服务：**

```bash
# 1) 几何（零模型调用，约 2.3s；--survey 复用存档即零调用）
cd ~/codes/ishome-aipipe
LITELLM_API_KEY=$LITELLM_MASTER_KEY uv run floorplan-geometry \
  --image services/genpipe-worker/samples/floorplan-brochure-92sqm-3b2l1b.png \
  --survey _iteration/run-2026-08-30-floorplan-geometry/geometry-1.json -o out/geo

# 2) 母版（零模型调用，确定性）
cd ~/codes/ishome-render2d
uv run render2d --geometry ~/codes/ishome-aipipe/out/geo/*-geometry.json -o out/master

# 3) 风格图（图生图；换风格＝换 --template，代码不动）
cd ~/codes/ishome-imagegen
set -a; source ~/.ishome/llm-local.env; set +a
LITELLM_API_KEY=$LITELLM_MASTER_KEY uv run imagegen \
  --master ../ishome-render2d/out/master/plan-master.png \
  --rooms ../ishome-render2d/out/master/rooms.json \
  --template templates/cream-journal.json -o out/style.png
```

`floorplan_copy.write_copy`。**叠字与说明图**在 render2d：`style_caption.render_caption`、
`plan_brief.render_plan_brief`。

两三个 `.py` 再 `systemctl restart ishome-chat`（**可编辑安装**，改源码即生效）；备份与回滚
一句话见《交接文档-用户发图到拿到报告.md》追记四。**同机跑着 aidcp 与 isales 生产服务，

## 十一、接手做什么

|---|---|---|
| render2d | `plan-2d-render` 是 `raise NotImplementedError`，只有 CLI 能画 | worker 真起、activity 真派，五件产物进私有桶；回读与本地纯库画的**逐字节相等**，重派两次键与字节都相同，无签名直取 403；几何清空外轮廓重派 → 响亮失败且**桶里一件没写** |

| channel-svc | 出站只认 `feishu-image://<image_key>`（飞书自家的图） | 统一消息带 `object_key` → 按键取桶字节 → 传飞书 `im/v1/images` 换回 image_key → 按原路发 |

### 三、这一趟真机踩到的三件

1. **aipipe 的 contracts 依赖锁在 v0.2.0，没有 `object_key` 字段**（正文 §九 坑单第 6 条写着它，
   这次撞上了）：拿 aipipe 的 venv 发消息报 `Protocol message ImageContent has no "object_key" field`。
   绕法＝`PYTHONPATH` 指到 contracts 仓的 `gen/python`。**抬版本的时点仍是那条：做"会话收到图、
   上报业务侧"那一段时**；
2. **本机起 channel-svc 会和 dev 服务器抢同一个飞书应用的入站事件**——长连接与发送挂在同一个
   `@ConditionalOnProperty` 上，**没有"只发不收"的模式**。这次抢赢了（业主那条 test123 进了本机库，
   open_id 从 `svc_channel.inbound_messages` 取到），但它是掷硬币。验完立刻停，把连接还回去；
3. **文档里那条起动命令有两个坑，都会让症状离原因很远**：`~` 在 `--args="…"` 双引号里**不展开**
   （要用 `$HOME`）；`optional:file:` 会把"凭证文件没读到"**吞掉**，于是飞书 adapter 整个不装配、
   发送时报 `NOT_FOUND`（注册表查无），看不出真因是配置没加载。去掉 `optional:` 让它当场失败。

### 四、留下来要拍的两件

1. **生成图的对象键形态**（我提的默认，不是裁决）：产物落在**源图同一前缀**下——

   `plan-rooms.json` / `plan-brief.png` / `atmosphere-{template_id}.png`。判据照 contracts

2. **扩展名到底跟不跟字节走**：风格图网关回来的是 **JPEG 字节，键却叫 `.png`**。现在按

### 三、出图模型评估（真跑 11 张、3.68 元；四仓零改动、无提交）

**结论：模型保持 `doubao-seedream-5-0-pro-260628` 不换。**判据一（图生图保构图）是门槛，
唯一能用现有钥匙实测的外部候选 qwen-image-edit-max 召回 52.6%/32.3%、要求写中文一个字没写，出局；

**换百炼不是改一行，业务代码要感知厂商，破变化轴 3**。三件此前没人记过的：

1. **`size:"2K"` 的长宽比由模型自己挑**（同参数回来三种比例）；显式像素尺寸→比例稳、

   减半，实测召回 94.1%（1184x2104）对 97.2%（1584x2816）——**降不降档等拍，显式尺寸本身怎么都要换**。
2. **防"静默退化成文生图"的守卫挂在 pro 独有的方言字段上**（`usage.input_images`，
   `5-0` 不返回、会被误杀）：换型号不是改 infra 一行，`image_gateway.py` 的守卫跟模型走。
3. **pro 支持在提示词里写归一化坐标** `<bbox>`/`<point>`（图宽高各切 1000 份）——房间质心现成，
