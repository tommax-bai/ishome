## 1. 总则：报告是什么

### 1.1 定义的修正

报告**不是一次性生成的文档，而是沿业主决策时序逐步产出的产物流的聚合容器**。此定义修正页面手册的隐含假设（一次生成+随行工具）。

**规则 1.1**：报告分两个生成阶段——

| 阶段 | 名称 | 触发 | 产物 | 定位 |
|---|---|---|---|---|
| stage-catalog | 户型级预生成 | 交付日历排产 | 户型档案、体检、通病、效果图套系、漫游 | 获客层：全小区同户型复用，用户"认领"即得 |
| stage-project | 家庭级定制生成 | 用户决策与需求采集驱动 | 平面比选→定稿→灯光→采购清单→水电清单 | 付费深化层：每个家庭一份 |

stage-catalog 是内容工厂的产物（供给侧逻辑不变）；stage-project 是决策时序状态机的产物。二者共用同一报告容器，stage-project 产物按里程碑逐步填充。

**规则 1.1a（v1.1 新增：容器分轨）**：stage-catalog 产物为 content-svc 公开发布物（全小区同户型复用）；stage-project 产物为 `svc_project.artifacts` 私有产物（"认领即分叉"后归单个家庭的项目真相）。"聚合容器"**仅在呈现层成立**（c-bff 报告页聚合两轨渲染），**禁止**为报告建任何统一跨轨存储——对齐原则一（公开内容与私有项目严格分轨）不因报告产品形态而破。

**规则 1.2（决策时序，承 v0.1 R-1.3）**：stage-project 出图顺序**必须**按业主决策时序而非施工时序编排：

```
愿景/效果图(要不要继续) → 平面布置比选(怎么住) → 平面定稿 → 灯光与立面材质(什么感觉)
→ 采购清单(买什么) → 水电点位清单+示意图(怎么盯施工) → 施工期清单族(验收)
```

每张图对应一个业主决策；每个决策产生一轮结构化反馈（"产物换反馈"）。

**规则 1.3（动作映射，承 v0.1 R-1.1）**：每个产物（页面/图纸/清单）**必须**映射到业主四类动作之一，映射不到的不进产物清单：

| 动作 | 含义 | 典型产物 |
|---|---|---|
| 决策 | 我的家要怎么住 | 体检、比选、效果图、灯光场景 |
| 表达 | 把需求翻译给装企/定制商 | 带尺寸平面、天花灯位图、立面意向 |
| 采购 | 尺寸驱动的购物 | 采购清单、灯具选型、货架 |
| 监督/博弈 | 审报价、盯隐蔽工程 | 报价检查表、水电清单、验收清单 |

**规则 1.4**：叙事弧不变：被看见 → 有问题 → 有救 → 能动手 → 有人陪。stage-catalog 覆盖前三段，stage-project 覆盖后两段。

### 1.2 专业感与力量感的生产原则

**规则 1.5**：专业感的来源定义为六项，全部**必须**由规则/数据驱动、可批量生产：①推导可见（分析图展示计算过程）②数字精确（见 §2.3 数字三分法）③制图规范（§3.2）④专业分章（六专章体系，§5.0）⑤材料规格化（§5.5）⑥比选有取舍（§5.3）。

**规则 1.6**：**禁止**以下伪专业形态：施工深化图纸（见 §3.4）、空泛概念叙事（"文化元素提炼"式话术）、无计算依据的专业术语堆砌。专业感靠密度不靠页数。

### 1.3 编号与命名规范（v2.1 新增）

**规则 1.7（语义命名）**：一切进注册表的标识符**必须**满足三条：

1. **带命名空间前缀**——前缀表明它是哪一类东西；
2. **主体是语义不是序号**——`art-lighting-chapter` 能读出意图，`D10` 不能；
3. **kebab-case、只增不改**——沿用 activity 注册名既有纪律（《架构审查-2026-08-24》§三）。

前缀全集（新增前缀须先进本表）：

| 前缀 | 类别 | 例 | 落点 |
|---|---|---|---|
| `art-` | 产物（图纸/专章/清单） | `art-lighting-chapter` | contracts 产物注册表 |
| `dom-` | 领域单元（生成轴） | `dom-lighting` | 域枚举，**同时是 release 发布粒度**（规则 4.12） |
| `pt-` | 页型 | `pt-moment` | 页型库 |
| `cr-` | 判据（校验项） | `cr-causal-link` | contracts rules 注册表 |
| `lkp-` | 求值落点 | `lkp-counter-height` | parameters 表键 |
| `gap-` | 求值缺口 | `gap-material-aging` | 回流记录类型 |
| `prec-` | 图纸精度等级 | `prec-schematic` | 枚举（§2.2） |
| `gen-` | 生成方式等级 | `gen-evaluated` | 枚举 `generation_mode`（§2.4） |
| `stage-` | 生成阶段 | `stage-catalog` | 枚举（规则 1.1） |
| `tier-` | 规则库三层 | `tier-mandatory` | 枚举（§4.1） |
| `acc-` | 内容准确性等级 | `acc-analysis` | 枚举（§2.1；中文分级名在文档内继续使用，进 contracts 时用此形态） |

**规则 1.8（四条禁止）**：

- **禁止**纯序号做标识符（`D01`、`P1`、`stage-project` 的旧名 `S2`、`L1` 这类）。旧编号只允许出现在 §14.6 历史对照表中；
- **禁止**前缀与语义重复（`art-drawing-lighting` 里的 `drawing` 是冗余）；
- **禁止**自造缩写，除非是行业通用词（`hydro` 可以，`lgt`/`chk` 不行）；
- **禁止**同一概念并存两套名——生成轴的领域枚举与专章域枚举**必须**收敛到同一套 `dom-`，否则 release 发布粒度分裂（规则 4.12）。

## 2. 三套正交分级体系

三套分级各管一件事，任何产物同时携带三个标签。

### 2.1 内容准确性等级（管"话能说多满"）

沿用页面手册七级：**事实级 / 分析级 / 概念级 / 参考级 / 清单级 / 操作级 / 安全级**。定义、生产者、话术规则见页面手册 §0.2，继续有效。

### 2.2 图纸精度等级（管"图能画多准"，承 v0.1 §2）

| 级别 | 含义 | 适用 |
|---|---|---|
| prec-exact 精确 | 给具体数字，误差可被决策容忍（±3-5cm 无影响） | 房间开间进深、平面布置家具尺寸 |
| prec-schematic 示意 | 只给相对位置和逻辑关系，**不出现定位数字** | 水电点位、开关插座、灯位 |
| prec-concept 概念 | 仅传达风格与氛围 | 效果图、愿景图、材质意向 |

**规则 2.1（承 v0.1 R-2.1）**：每张图纸图框内**必须**印刷精度级别及说明文案（§7）。

**规则 2.2（承 v0.1 R-2.2）**：精度降格是主动设计。prec-schematic 图纸上出现定位数字，业主会当作施工指令，示意图即退化为错误的施工图。渲染层**禁止**在 prec-schematic 图纸输出任何定位标注。

### 2.3 数字三分法（解决 prec-schematic 禁数与专业数字的冲突）

**规则 2.3**：全报告的数字分三类，各有专属领地：

| 类别 | 定义 | 允许出现处 | 示例 |
|---|---|---|---|
| 定位数字 | 施工定位用的坐标/距离/高度 | **仅 prec-exact 图纸** | 开间3.9m、沙发2.4m |
| 选型数字 | 驱动购买决策的商品参数 | 采购清单、灯光选型页、货架；**禁止上 prec-schematic 图** | 色温3000K、光束角24°、吊灯下沿距桌面700-800mm |
| 分析数字 | 规则计算的结论，须可溯源到计算 | 分析图与正文 | 冬至日进深4.2m、收纳0.23延米/㎡、重点照度=环境3-5倍 |

灯光专章的专业数字全部属于选型与分析数字，与 prec-schematic 灯位图的定位禁令不冲突——**数字下清单，位置上示意图**。

### 2.4 生成方式等级（管"谁被允许生产内容"）

**规则 2.4**：生成方式定义为五档，每个组件在 contracts 中携带 generation_mode 字段：

| 档 | 名称 | 定义 | 适用 |
|---|---|---|---|
| gen-locked | 枚举锁定 | 引用锁定文案ID或结构化数据直接渲染，零生成 | 安全级全部、免责文案、户型参数 |
| gen-evaluated | 规则求值 | 纯规则遍历，**必须可重放**（同输入同输出，承 v0.1 R-4.1） | 清单族、人体工学校核、体检评分、预算计算 |
| gen-assembled | 规则计算+句式拼装 | 计算结果填入**系统自产句式**（句式=回流固化的 release 数据，非人写模板，规则 4.17） | 体检结论句、日照分析、比选影响估算 |
| gen-generated | AI生成+机检+当事人校验（v1.1 修订，原"AI生成+人审"） | genpipe 出多候选→打分→机检门禁（consistency/compliance/scorer）；交付/发布前的人为判断只有**当事人校验**（用户确认、比选选择）；句式质量由**自动回归门禁**把关（种子集回归 + 观察态发布，规则 4.17），无验收台、无人工环节（v2.0） | 效果图、漫游、风格叙述、pin文案 |
| gen-polished | AI润色（语义锁定） | LLM 仅改措辞**不得改变语义**（承 v0.1 §4） | 清单条目的 rationale_display |

**规则 2.5（组合约束矩阵）**：安全级→仅gen-locked；清单级→gen-evaluated（+gen-polished润色）；操作级→gen-evaluated；参考级→gen-evaluated/gen-assembled（v1.2：造价区间填句式）；分析级→gen-evaluated/gen-assembled；概念级→gen-generated；事实级→gen-locked。违反组合的组件在 contracts 校验层拒绝。

## 4. 清单产物族：统一规则库架构

art-hydro-checklist/art-quotation-checklist/art-acceptance-checklist（及 art-purchase-checklist 的规则部分）**必须**共享同一套规则库架构。这是对 v0.1 §3.3 的推广：水电清单的 tier-mandatory/tier-practice/tier-personal 三层结构上升为全清单族的通用架构。

### 4.1 规则三层与触发模型

| 层 | 内容 | 来源 | 示例 |
|---|---|---|---|
| tier-mandatory 硬约束 | 国标/行规强制项 | GB 50303、GB 50242 等一次性整理 | 卫生间局部等电位联结；厨卫空调独立回路；防水淋浴区高度1.8m |

**规则 4.3（可追溯性，承 v0.1 R-3.2）**：需求触发的条目**必须**携带 `triggered_by` 指向具体采集答案；产品层用它渲染"因为你提到平时在家办公"——**"你说过的话变成了图上的东西"是 stage-project 的核心信任机制**，与 prec-schematic 封面的参数回显、P6 风格叙述引用参数是同一原则的三个落点。（v1.1 注：答案落 `svc_project.slots` 后，`triggered_by` 即答案槽位的 `source_event_id` 溯源链，见规则 6.4，机制现成。）

### 4.4 知识资产五形态与统一治理（v1.2 新增）

专章丰富度的本体是知识密度，知识密度的本体是库。**"知识库"不落成文档库，落成结构化知识资产**：按形态分五类建模（§4.1 的规则库是其一），加域级 persona 资产包，统一治理头。**v2.0：无编辑后台、无运营维护**——获取、核验、发布、迭代全部由系统自动完成（规则 4.16/4.17）。

**规则 4.9（五形态）**：领域知识按形态拆分建模：

| 形态 | 管什么 | 示例 | 产出方式（v2.0：无人无运营） |
|---|---|---|---|
| rule 规则 | 触发→条目（§4.1 三层三触发） | 有猫→喂食点位；开放漆×油烟区禁忌 | 系统编译（tier-mandatory 抓标准条文锁定，tier-practice/tier-personal 自产+信号迭代） |
| parameter 参数与公式 | 计算依据与数值区间 | 台面高=身高/2+50~100；工作三角3.6-6.6m；重点照度3-5×环境；60-30-10 | 系统编译 + 机检核验 |
| attribute 属性库 | 实体×属性的参考数据 | 材质属性卡、色板卡、收纳物品尺寸、工项单价区间（带城市档+时效） | **系统自动获取**（外部数据源+交叉验证+时效刷新，规则 4.16） |
| template 句式库 | gen-assembled 拼装句式 | "冬至日正午，阳光可达{zone}（进深{d}m）" | **系统自产**（生成回路固化，非人写；规则 4.17） |
| vocabulary 词表 | 受控词汇 | 规格词表（规则 5.10）、修订维度词表、色彩命名 | 系统自动获取+自产（货架实际在售词面回流） |

外加**persona 资产包**（域级语域配置：口吻/判断句风格/断言预算/禁词表），版本化，统一约束该域的 gen-assembled 模板句、gen-generated 叙述与 gen-polished 润色——"专家口吻"由它保证，不靠运行时自由发挥。

**规则 4.10（治理头）**：每条资产**必须**携带统一治理字段：

```yaml
knowledge_asset:
  id / domain / form: rule | parameter | attribute | template | vocabulary
  version
  source: "GB 50303 | 人因工程惯例 | 行业惯例 | 自有沉淀"   # 依据出处——推导可见的数据源
  calibration: draft | calibrated | needs_review
  consumers: [...]                    # 双向校验依据（规则 6.1 推广到全形态）
  effective_from / effective_to       # 时效资产必填（单价库强制）
```

**未校准（draft）资产照常进入产物，随呈现标注依据与取数时间——不隐藏**（v2.4 裁决 2026-08-29，**推翻 v1.2 起的"未校准资产禁止进入 PAID 产物，只能降档呈现或隐藏该条目"**）。

判据是产品形态：报告给业主的是**建议**。一条藏起来的建议**对业主零价值、对系统零信号**——规则 4.17 的行为信号全部来自业主对内容的反应，没有内容就没有反应，于是**藏着的条目永远等不到转正信号**，规则 4.10a 的升级路径在冷启动期成了死循环（藏起来 → 无信号 → 转不了正 → 继续藏）。建议有问题的正确处置是**下一轮调整**，不是替业主决定他看不见。

**取消的是纪律的形态，不是纪律**：原纪律"没依据就别说"改为"**说了就必须标**"——依据与取数时间随落点下发、随正文呈现，业主自己判断这条有多硬。执行判据见规则 4.10c。

**规则 4.10a（可核性门，v1.4 新增；替代原"逐域执业者校准"）**：条目按依据可核性分两类，`calibrated` **只能由机检核验取得，全流程无人工签字门**：

| 类别 | 判据 | 上线形态 |
|---|---|---|
| **可核条目** | source 指向可定位的外部依据：国标/行标条文号、检测标准指标（色牢度、马丁代尔、地材耐磨等级）、厂商公开参数、设备标准尺寸、公开单价数据 | 过核验跑批 → `calibrated` → 可作判断句背书（规则 4.13 断言预算），**语域可用标准口吻**（"国标要求不低于…"） |
| **经验条目** | 无外部依据、靠行业判断（如"这种柜门在油烟区两年后的样子"） | 恒为 `draft` → **照常呈现、随标注**（规则 4.10c，v2.4 修订），**语域限建议口吻**（"我们建议…"），不进断言预算 |

**核验跑批四项**（全自动，入库时与 CI 双跑，无人工入口）：①`source` 非空且指向可定位依据（标准号/条文号/指标名/数据源）②数值区间自洽，不与同域其他条目互相矛盾 ③单位与量纲合法 ④`consumers` 双向校验通过（无孤儿条目、无悬空引用）。

**经验条目的升级路径唯一**：埋点信号累积达阈值（当事人校验，§4.5 回流）→ `needs_review` → 复审出新版本。**禁止**以"内部评审通过""专家人设已确认"为由把经验条目置 `calibrated`。

**代价明示（v2.4 重写；原文"经验性判断初版进不了 PAID 判断句，只能以参考形态出现或缺席"作废）**：经验性判断（材质"两年后的样子"、软装搭配惯例）**照常出现在报告里**，受限的是**语域不是存在**——它只能以"我们建议"出现，不能以"国标要求"出现。calibrated 区分的是**说话的底气**，不再是**说不说**。专章密度仍靠可核条目铺主干，经验条目靠埋点信号逐步转正——**收窄的是断言强度，不再是收录范围**。

**规则 4.10c（未过门条目的标注判据。v2.3 新增时名为"降档与隐藏的判据"，v2.4 整条重写为"标注"）**：

> **v2.3 原判据全部作废**（记此供审计）：原表按"能不能以参考形态说出口"分档，其中三条判**隐藏**——①未过门 × PAID × 定位数字；②未过门 × PAID × 值里任意层级都找不到区间；③判不准。三条随 v2.4 裁决一并取消，理由见规则 4.10。原表另有一句"隐藏 ≠ 求值缺口，禁止并入 `gap-`"，其分流精神在新判据下由 `provenance` 与 `gap-` 各自承载，不再需要第三个集合。

新判据如下，**在消费侧（求值线出包时）强制执行**，产出随落点对象下发：

| 条件 | 呈现 | 依据 |
|---|---|---|
| `calibrated` | 可作判断句支点，**语域可用标准口吻**（"国标要求不低于…"） | 它是断言预算唯一合法的背书来源（规则 4.10a/5.8） |
| 未过门（`draft`） | **照常下发**；落点随带 `source` 与 `effective_*`，**语域限建议口吻**（"我们建议…"），不进断言预算 | 建议是产品形态（规则 4.10）；标注让业主自己判断这条有多硬，而不是替他决定他看不见 |
| 时效越界（`effective_to` 已过） | **照常下发**，标注**取数时间**与来源 | 过期数据仍是它当时的真实行情；标了时间业主自己会折算，抹掉反而少给他一个判断维度 |
| `conflict`（源间互斥） | **不进 release**（v2.3 口径不变，规则 4.16①） | 标注解决不了两个源各说各话——标哪一个都是替业主选边，而这里连"我们的建议"都还不存在 |

**标注必挂（新纪律，替代原隐藏档）**：`draft` 或已过期的落点出现在正文的，**同一页必须同时出现它的依据标注**（来源 + 取数时间）。这是**确定性判据、机检可判**——落点带 `provenance`，页上有没有对应标注可逐条比对。**未标注即违规**；它是原隐藏禁令的等价物，拦截点从"说出来"移到了"不标就说"。

**为什么标注够用而隐藏不够用**：隐藏拦的是"业主看到没依据的数"，代价是他连这条建议都拿不到；标注拦的是"业主**误以为**这个数有依据"——而这才是风险真正所在。业主拿一个标着"行业常用值、开工前请现场复核"的台面高度去施工，和拿一个不标的去施工，是两件事。安全级话术（§7 锁定文案 `GUIDE_SITE_CHECK` / `DISCLAIM_P1`）本就是为这个场景准备的，与本条配套使用。

**回流优先级**：获取回路的补依据队列改读"**`draft` 且已进正文**"的落点——它们正是最该补依据的，因为已经在对业主说话了。v2.3 的 `withheldAnchors` 审计集因不再有内容而**恒空**，字段按契约"只增不删"保留（见 §14.9）。

**成文线侧的对应强制（v2.4 修订）**：判断句须**显式声明**所用的断言预算谓词，且该谓词 requires 的落点全部已求值且为 `calibrated`——**这一条不变**：断言预算管的是"以什么底气说"，不是"能不能说"，未过门的落点照常进正文、照常给建议，只是不能拿来当"国标要求"的支点。原文"主旨句的数字支点必须全部是可作支点档"随隐藏档取消而失效（未过门落点已可进主旨句，条件是随页标注）。注：**"这句话算不算判断句"没有确定性判据，机检不假实现**——语义识别归判官层（图 v0.2 §3 分域反例库）。机检只保证"声明了就必须有背书"，不保证"没声明就不是断言"。

**规则 4.10b（纪律与知识的边界，v2.2 新增）**：calibration 状态机**只适用于知识断言**——关于世界的陈述（rule/parameter/attribute 的内容条目），它们可能是错的，所以需要外部源或用户信号背书。**纪律**——系统对自身输出的约束（禁令、降档、必挂文案）——不是知识断言，没有对错可核，**禁止以知识条目形态入库**：

- **纪律的唯一存在形式**：机检 check（确定性拦截/降档规则）或 gen-locked 锁定文案。不进 calibration 状态机；正当性锚 = `decided_by` 字段指向裁决记录（规范条文号 + 裁决日期），随域 release 版本化、可回滚。
- **结构性防伪装**：check **不得携带内容数值**——数值阈值只能引用 parameter（`lkp-*`，如 `max_from`），该参数照常过可核性门（规则 4.10a）。想把经验判断（"色温≤3 种"）伪装成纪律绕过核验，结构上没有放数字的位置，不可行。这是物理隔离信条在核验体系的形态：不设判别规则，让作弊无处落笔。
- **判别归谬**：一条目若无外部源且无信号路径——要么它能改写为确定性 check（那它是纪律，移过去），要么它是经验条目、老实待在 draft。**不存在第三类，不设"纪律型知识条目"。**

**规则 4.11（两个反模式，禁止）**：
1. **禁止文档库+RAG 检索进入运行时生成链路**。检索不保证取全——清单漏一条 tier-mandatory 是事故；检索结果不可重放；无人审体系下自由生成无兜底。RAG/检索仅允许在**资产回路内**（规则 4.16 获取阶段）辅助起草，产出仍须落成结构化资产过可核性门（规则 4.10a）；**禁止**出现在报告生成链路。
2. **禁止通用知识平台/单一大表**。五形态 schema 异构、刷新节奏异构（单价按月、参数按年、词表随货架），按形态各建各表；"配置只放数据，逻辑归服务，不建通用平台"。

**规则 4.12（存在形式：库表真相 + 域级发布快照，v1.3 细化）**：

- **存储**：五形态+persona 全部落 PG `svc_rulebook` schema 六表族（v2.2 注：check 形态按规则 4.10b 增设第七表——无 calibration 列、`decided_by` 非空、数值阈值只经引用 parameters；另设 releases 表承载域级不可变快照，为运行时唯一读取面）（project-svc 规则引擎模块持有，§11.3；schema 独立=将来可整体拆走）。attributes 表以 entity_type（material/color/storage_item/work_item…）+ JSONB 属性包承载异构实体，**不按实体类建表**；各 entity_type 的属性 JSONSchema 入 contracts。
- **工作态与运行态分离**：资产回路写入的是工作副本（draft/calibrated 状态机，**无人工编辑入口**）；运行时求值**只读域级发布快照（release）**——发布动作把该域资产固化为一个不可变版本（如 `ergonomics@v3`）。可重放、版本锁定（规则 8.2）、"升级不追溯+用户主动刷新"三件事全部由 release 的不可变性承载。发布粒度=domain，一域一版，互不牵连。
  **快照收录范围（v2.3 裁决订正，原文"全部 calibrated 资产"与规则 4.10 的降档路径冲突）**：快照**含 draft 条目并携带 calibration 标记**——不含 draft，则规则 4.10 的"降档呈现（如参考级区间）"没有实现基础，造价章（参考级区间＝draft 单价的降档形态）等整章消失。draft 条目能不能出现、以什么形态出现，由**消费侧门禁**按规则 4.10c 判定。**唯一的例外是 conflict 条目**（规则 4.16①）：源间互斥的条目**不进快照**——draft 是依据不足、尚可降档，conflict 是两个源各说各话，降档也无从降起（参考形态呈现的仍是一个没有共识的数）。
- **消费路径三条，无运行时跨服务拉取**：①project-svc 规则引擎（gen-evaluated/gen-assembled）进程内读本库 release；②genpipe（gen-generated/gen-polished）所需 persona 约束由 project-svc 创建生成任务时写入 input_snapshot 随任务下发（生成侧不知用户是谁、不回查库）；③chat-svc 不读 rulebook——问题集与词表走流程定义配置既有分发（规则 6.4），question↔rule 双向校验为 CI/后台跑批。
- **contracts 只进契约不进内容**：各形态的 JSONSchema、domain/form 枚举、release 引用格式入 contracts；条目内容是数据，不随仓评审。
- **首批建库入口=种子文件**：系统编译产出 YAML 种子文件入仓（可审计、可 diff），导入脚本灌库后 **DB 即唯一真相**，种子文件封存为初版审计记录，不做双向同步。此后一切增改走资产回路（规则 4.16/4.17），不走人工。
- 视觉模板库（ViewSpec）**不并入**——知识资产管"说什么"，视觉模板管"画成什么样"，边界保持。

### 4.5 知识资产回路（v2.0 重写：全自动，无运营环节）

```
外部获取（标准条文/检测指标/厂商参数/公开单价） ┐
系统编译（LLM 起草，每条带 source）              ├→ 机检核验 → release 快照 → 运行时纯求值
自迭代产出（句式/判据/禁词，规则 4.17）          ┘                              │
        ↑                                                                       │
        └──────────── 自动复审（needs_review）←──── 用户行为信号 ←──────────────┘
```

- **系统编译**：每领域一个域身份配置（照明/人体工学/材质/收纳/软装/造价），由模型按该身份从标准条文、人因工程数据、行业公开资料**批量编译**结构化条目，每条带 source 与置信。**产出的是数据不是文案**——可核与否由规则 4.10a 判定。编译是回路的一个阶段，不是一次性的"设计时动作"，可随外部数据更新自触发重跑。
- **可核性门（v1.4 修订）**：`calibrated` 由机检核验跑批取得（规则 4.10a），无人工签字环节。原"逐领域执业者一次性校准"**作废**——项目无可依托的执业者资源，该门在此前提下即空门，与运行时人审是同一种失效形态（V1.3 判据：人审是设计者的零成本对冲）。库的可信度改由**只收可核条目**承载。
- **运行时消费**：纯求值。丰富度 = 库的密度 × 个性化触发，不靠临场发挥；密度增长由回路承担，不由人补。
- **数据回流**：用户行为信号驱动自动复审——tier-practice/tier-personal 条目高"不做"率、item_confirmed 低覆盖、货架高换款率标签、比选高频调整维度 → 自动置 `needs_review` → 回路重编译该条 → 过核验 → 出新版本。**无复审队列、无人工介入**。库漏掉的问题，出路是迭代库，不是加人。

### 4.6 persona 资产包的形态与维护（v1.3 新增）

**规则 4.13（persona 形态）**：一域一份结构化配置（personas 表，随域 release 发布），内容四件：①身份与语域描述（gen-generated/gen-polished 的系统 prompt 片段：域身份、口吻、人称）②判断句风格样例（好/坏对照句对，规则 5.8 的域内实例化）③断言预算（何时允许判断句：须有 gen-evaluated/gen-assembled 计算背书的谓词清单）④禁词表（弱词/越权承诺词/责任话术词）。

**规则 4.14（persona 维护 = 自动回归门禁，v2.0 重写）**：persona 走自动门禁发布，**不设逐份样张的人工验收环节**；方向可以来自人（规则 4.19）：
- **修订入口（二者并存）**：①回流信号自动触发（域内负反馈埋点、gen-polished 语义漂移检出率、禁词命中率、读者代理判"没带走"率）；②产品/开发角色提出方向，由 AI 起草修订稿。两条入口过同一套门禁，不因来源是人而豁免；
- **自动预检**：种子集（golden set：代表户型×家庭画像）重跑该域全部 gen-assembled/gen-generated/gen-polished 输出，机检两道——语义锁定比对（结构化字段与关键数字零漂移）+ 禁词扫描；
- **回归门禁**：不得把种子集正例判违规、不得放过种子集反例（规则 4.17）；
- **观察态发布**：先只记录不拦截跑 N 份，触发率为零或超阈值自动退回；
- **发布**：随域 release 快照，产物锁版本，回滚=切回旧 release。

**规则 4.15（禁词表双消费）**：persona 的禁词表既是 prompt 约束，也**必须**编译进机检门禁的措辞扫描（与五仓措辞红线 grep 同源纪律）——persona 不只是生成素材，也是机检规则的数据源。
迭代信号：域内文案负反馈埋点、gen-polished 语义漂移检出率、禁词命中率 → needs_review 复审队列，与 §4.5 生命周期同构。

### 4.7 三条回路与人的位置（v2.0 新增：系统运行不依赖人；系统迭代由人与 AI 共同驱动）

**规则 4.19（人的位置：产品/开发，不是运营）**：本规范的"不依赖人"指**系统运行不依赖人**，**不**指系统迭代不依赖人。判据只有一条——**这份人力是否随用户量增长**：

| | 形态 | 判定 |
|---|---|---|
| **禁止** | 逐实例审核、逐份报告验收、逐条目录入、需常驻编制维护的后台台账 | 随用户增长，必然失效（V1.3 判据） |
| **允许** | 人驱动 AI 修改设计文档与资产定义，一次改动全量生效 | 不随用户增长，这就是开发与产品 |

- **入口形态**：人的改动走 **人驱动 AI 改源 → 编译成数据 → 过核验 → 发 release** 这条版本化路径（与种子文件同模式，规则 4.12）；**禁止**运行时热改与后台逐条点选。
- **《装修报告生成方法论》及四分册的位置由此确定**：**设计文档，不是运行时输入**。它是人与 AI 的共同工作面；系统消费的是由它编译出的 persona / 句式 / 判据 / schema，**手册文本本身不进 prompt**。手册之于知识资产，等同于种子文件之于库：可审计、可评审、可 diff，编译入库后 DB 为唯一真相。
- 与规则 4.16/4.17 的关系：回路负责**自动**的那部分（外部事实获取、信号驱动的句式与判据迭代）；人负责**方向与重写**的那部分。两者共用同一套发布门禁（核验 + 种子集回归 + 观察态），不因来源是人而豁免。

**规则 4.16（获取回路：外部事实自动进库）**：一切有外部真源的条目（attribute、parameter、rule 的 tier-mandatory 层）由系统自动获取，**不设运营录入**：

- **源**：标准条文文本、检测标准指标（色牢度/马丁代尔/耐磨等级）、厂商公开参数、公开单价数据、货架在售商品参数。
- **三道自动校验**：①**交叉验证**——同一指标须 ≥2 个独立源一致才入库，不一致挂 `conflict` 且不进 release（v2.3 落地口径：`conflict` 是资产表的独立列，**与 calibration 正交**——发布时排除出快照、核验时一律不够格转 `calibrated`；"两个都能定位、彼此打架的源"，定位性不构成可核性）；②**时效**——`effective_from/to` 必填，过期自动置 `needs_review`；③**可定位**——`source` 必须能回到原文位置（标准号+条文号/指标名/数据源），否则不予 `calibrated`。
- **刷新由节奏自触发**（单价按月、参数按年、货架随抓取），无人工排期、无运营台账。

**规则 4.17（自迭代回路：句式、判据、禁词由系统自产）**：

- **产出物**：gen-assembled 句式、机检判据、persona 的禁词表与判断句样例。三者都是**数据**，随域 release 发布，可回滚。**人不写其中任何一条。**
- **信号源**（全部机器可得）：①用户行为——追问、修订、换款、跳读、比选调整维度、清单现场勾选覆盖、付费与分享；②**读者代理**——不持有任何判据，只被设定为该家庭，逐页回答"我带走了什么／哪句读不懂／哪句在让我做事／读完想问什么"；机检判合格而读者代理判"没带走"的交集 = 判据未覆盖处；③跨报告失败聚类——同类失败反复归入"其他"说明判据切分不对。
- **入册门禁（防自我漂移，三道）**：①**种子集回归**——不得把种子集正例判违规，不得放过种子集反例；②**观察态**——先只记录不拦截跑 N 份，触发率为零或超阈值自动退回；③**每轮入册上限**，避免判据爆炸。
- **品味锚点**：品味的**提出**可以来自人（产品角色）或回路；品味的**验证**只能是转化与行为信号（付费、分享、修订收敛、追问下降）。**禁止**以内部评审结论或模型自评分**替代**信号验证——判官与写手同源，自评分必漂；人的判断同样需要信号回证，只是不必等信号才能动手。
- **种子集**：初版来自冷启动期问题样本；随真实信号积累逐条替换为"信号标定过的真实案例"。**种子集是回路的上限**，其真实度决定系统能发现的问题维度——这是本设计已知的天花板，写明而不掩饰。

**规则 4.18（冷启动，v2.0 新增）**：首份报告发出前无任何行为信号。此期间：

- **（v2.4 重写；原文"只发可核条目支撑的内容；经验性判断整批降档或缺席"作废）** 经验性判断**照发并标注**（规则 4.10c）。冷启动期恰恰最需要内容出去换信号——藏着的条目等不到行为信号，规则 4.10a 的转正路径在冷启动期会变成死循环。**保留的是密度纪律**：不许用无背书判断句撑密度（规则 1.6），其 v2.4 形态是"**不许不标注就撑密度**"。
- 质量上限 = 自我评测质量。据此**主动收窄产物范围**——宁可章节少、页数薄，不可用无背书的判断句撑密度（与规则 1.6"密度不靠页数"同源）。
- **退出判据写死**：某域行为信号量达阈值后，该域经验条目方可走转正路径（规则 4.10a），不到阈值不转。
- **（v2.5 增补 2026-08-29 晚）无背书题目的呈现形态＝坦白缺口**：断言预算之外的题目若要出现，**只许坦白**——直说这轮给不出可靠结论、取决于什么、等什么（依据限包内可知事实：哪些落点仅参考口吻、哪些求不出，**不编原因**）。**禁止**"描述现象但不下判断"式硬写——实测产物是元语言与伪因果填空（真跑逐字证据见《评审/造价灯光失败归因与待裁点-2026-08-29.md》例证节）。坦白对业主是真实的预期管理，与 v2.4"不隐藏"同一条产品逻辑。

## 5. 内容深度模块（专业感决议的规范化）

### 5.0 专章范式（v1.2 新增，从灯光专章提炼）

**规则 5.0（六专章）**：报告专业深度由六个专章承载（用户裁决 2026-08-23：五章全上）：art-lighting-chapter 灯光（既有标杆）、art-ergonomics-chapter 人体工学（升格）、art-material-chapter 用材、art-storage-chapter 收纳、art-color-soft-chapter 色彩软装、art-budget-chapter 造价。每章四节结构（细则 §5.1/5.2/5.6-5.9）**（v2.5 改判：四节为满配形态——节的存在由该节数据背书决定，数据不齐的节以坦白缺口形态出现或缺席，判据同规则 5.0b"四件不齐不发布"抬至节级；原文"固定四节"对照留此，§14.10）**。

**规则 5.0a（五要素）**：每个专章**必须**配齐：①领域知识资产（§4.4 五形态按域配齐）②固定章节结构 ③分析数字+选型数字、推导可见（source 上图）④个性化触发（triggered_by 渲染"因为你说过"）⑤联动件（采购/表达/监督至少其一）。

**规则 5.0b（付费测试）**：每章每页过"**图 + 数据 + 判断 + 个性化**"四件齐检验，四件不齐的页不发布——宁缺勿滥，密度不靠页数（规则 1.6）。

**规则 5.0c（领域生成器）**：每章一条领域生成管线 = persona 资产包 + 章节流程 + 域知识资产。各域**逻辑同构**（触发→求值→拼装→润色），**一台引擎挂 N 个域资产包，禁止按域拆生成服务**——物理拆分判据是逻辑异质，此处仅数据异构（与绘图三服务的拆分判据互为反例对照）。

### 5.1 灯光设计专章（art-ceiling-lighting-plan+art-lighting-chapter，专章范式标杆）

### 5.9 造价预估专章（art-budget-chapter，v1.2 新增）

**规则 5.15**：四节结构**（v2.5：满配形态，同规则 5.0 改判——当前数据现实下四节无一节齐，先出得起哪节出哪节，无背书题目按规则 4.18 坦白缺口呈现）**，造价域知识资产驱动（budget domain，quotation 域规则复用）：

**数据源（用户裁决 2026-08-23：公开数据起步）**：单价库首版取公开数据（各地信息价、公开装修报价行情、电商主材公开价），每条带 source 与 effective；**置信按 source 分级，区间宽度随置信调整**（低置信=更宽区间，parameter 化）。合作装企回价与自有成交数据回流为后续迭代方向——区间收窄即产品力提升点。

## 8. 生成管线与时序

**规则 8.1（三层落点，v1.1 按 V1.5 裁决重写）**：
- **项目层**：stage-project 决策时序状态机 = **project-svc 里程碑引擎的流程定义**（process_version 项目创建时固化；事件驱动 checkCompletion——读判据配置→查 slot/artifact 表→布尔求值→迁移+on_enter 编排；真相在表）。链条 `认领 → 需求采集(渐进) → 比选中 → 平面定稿 → 灯光/采购展开 → 水电交底 → 施工陪跑(七阶段) → 入住` **必须**与既有里程碑（确认闭环→初步方案→深度设计）合并为**同一份流程定义**，**禁止**报告域自带第二台状态机。产物依赖以判据配置表达：`hydro_checklist` 依赖 `floor_plan_final` + 需求槽位集齐。（v1.0 原文"落 genpipe-svc 的 Temporal workflow 之上"作废——V1.5 裁决长周期 workflow 方案作废，Temporal 收缩至任务层。）
- **会话层**：需求采集对话归 chat-svc（规则 6.4），输出结构化答案事实 → project-svc 落 slots。
- **任务层**：仅 gen-generated 产物进 genpipe Temporal workflow 异步生成（重试/心跳/超时原生语义），派发三绘图服务（落点映射见 §11.7）。gen-evaluated/gen-assembled 产物同步可算，**不进异步队列**（里程碑 on_enter 或接口请求内直接求值）。

**规则 8.2（v1.1 修订：删人审）**：stage-catalog 排产流程 = 标注→批量生成→打分→**机检门禁**→空间级发布（v1.0 原文含"人审"环节，按 V1.3 裁决删除；v2.0：句式与模板质量由自动回归门禁把关，无验收台）。stage-project 的 gen-generated 产物质量门 = **机检门禁 + 当事人校验**——比选选择（规则 5.7）与定稿确认即校验动作，不设额外人审门。gen-evaluated/gen-assembled 产物免质量门但**必须**过知识资产版本锁定（v1.2 扩展）：产物记录生成时消费的全部知识资产版本集（规则/参数/属性/单价/句式/persona，落 `svc_project.artifacts` 的 gen_params/lineage 快照，机制现成），资产升级不追溯已交付产物，用户可主动刷新。

**规则 8.3**：每个 stage-project 决策节点完成时触发一轮反馈采集（选择+调整意见），反馈结构化入需求槽位，驱动下一节点。**禁止**无反馈直接推进定稿。（落点：chat 受限映射反馈事实 → project-svc 落库触发里程碑引擎，即既有"产物换反馈"闭环。）
