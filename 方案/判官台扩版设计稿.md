## A. 信息架构

### A-1 原则（三条，全部承既有裁决）

1. **不新建第二个后台，判官台扩版**。今天判官台的三栏（左列表 / 中主体 / 右判定）和"判完才显示 AI 判官结论"照旧，只把主轴从"样本集"换成"AI 判断"。【方案 §〇.3、§七；B12 适用范围说明：判定/检查页面许做网页】
2. **一页只回答一个问题**。下面每页写明它回答什么；同一页不混"汇总比率"与"单条判定"。【CLAUDE.md 纪律·一份文档只回答一个问题，借用到页面】
3. **网页上只出"数量"，不出"比率"，唯一例外是单处 AI 判断的一致率页**。总览列的是记录数/用例数/未判数（工作队列），不列通过率；跨 AI 判断的汇总比率按 9-04 裁决先落 CLI/json，等第二个看的人出现。【B12；方案 §四·展示；方案 §六.1 待你决定】

### A-2 页面清单与导航层级

```
总览  /                                 —— 哪处 AI 判断现在有多少东西等我看
├── 没标明来源的记录  /unclaimed          —— 调用记录里没带 AI 判断名的那些是什么
└── AI 判断页  /p/<point>                —— 这处是干什么的、我给它留了哪些测试用例、各自跑成什么样
    ├── 线上真实记录  /p/<point>/ledger   —— 它最近在线上答了什么（挑测试用例的来源）
    │   └── 记录详情  /p/<point>/ledger/<record>   —— 这一次调用发了什么、收了什么、从哪儿发的
    ├── 用例页  /p/<point>/cases/<case>   —— 这份输入再跑 N 次答得稳不稳、哪种检查拦住了
    │   ├── 对比  /p/<point>/cases/<case>/compare?runs=a,b   —— 两次模型回复差在哪
    │   └── 判定页  /p/<point>/cases/<case>/runs/<run>       —— 这一次的模型回复错没错
    └── 一致率  /p/<point>/agreement      —— 机器（格式/规则/AI 判官）与我判得一不一致
旧样本集  /sets/<set_id>                  —— 现有三集照旧打开（demo / demo138 / stage2-consult）
```

- 顶栏常驻：`判官台 · 总览 · [当前 AI 判断 ▾] · 未判 N · ⌕`。AI 判断下拉按业务线分组（会话 / 获客 / 三维 / 报告 / 判官台自身），与方案 §一表同序。
- 左栏永远是"同级列表"（记录列表 / 用例的各次列表），中栏是"被看的东西"（发给模型的内容与模型回复 / N 次表 / 回复正文），右栏是"判定与位置"。今天的三栏就是这个分工，不改。【判官台 index.html 现状】
- `<point>` 用基本信息表里的拟定名（`chat-intent`、`floorplan-survey`……），前缀即命名空间。【方案 §四·基本信息表；红线·命名禁纯序号】
- `<record>` = 调用记录 id（模型网关的请求 id + 日期，如 `20260909-1140-a3f9`）；`<case>` = 语义化的网址名（见 C-①）；`<run>` = `线上那次` 或 `再跑-<批次时间>-<序>`（序号只作定位）。
- 旧的 `/?set=` 继续 302 到 `/sets/<set_id>`，三个现有集不迁移；它们的用例若带 `call.point`，也会出现在对应 AI 判断页里。【方案 §四·测试用例："形态在现有 cases.json 上加 call{...}，图类用例不变"】

### A-3 每页回答什么、放什么、不放什么

| 页 | 回答的问题 | 放 | 不放 |
|---|---|---|---|
| 总览 | 该先看哪处 AI 判断 | 12 行基本信息摘要 + 近 7 天线上记录数 / 用例数 / 未判次数 / 最近一次失败时间 / 自动检查是否已导出 | 通过率、一致率、趋势【B12】 |

| AI 判断页 | 这处是什么、用例都有谁 | 基本信息全行（默认折叠只露两行：要模型回答什么 / 不许决定什么）、用例列表（来源、跑数、未判、最后一次三种检查结果）| 线上真实记录（另一页）|

## B. 核心对象与状态机

### B-1 对象一览

```
AI 判断 CallPoint ──1:N── 线上真实记录 LedgerRecord ──存为──▶ 测试用例 Case ──1:N── 一次 Run ──1:1── 检查结果 Detection{格式,规则,AI 判官}
                                                          │ 改坏输入得到新用例          └──0:1── 人工判定 Label
                                                          ▼
                                                        测试用例 Case(source=改坏的输入, parent=…)
一致率 Agreement = 按 AI 判断，对"人工判定 × 每个检测器"的算式，不是存储对象
```

| 对象 | 谁生它 | 谁改它 | 存哪 |
|---|---|---|---|
| AI 判断 | 基本信息表（contracts 或判官台，方案 §六.5 待你决定） | 判官台只读 | 基本信息表 json |
| 线上真实记录 | 模型网关的记录 callback | 不可改，只能被"挑" | `/opt/ishome/llm-ledger/` 按天 jsonl【方案 §四·调用记录】|
| 测试用例 | 用户（挑 / 改坏 / 从考卷导入） | 输入锁定前可改，锁定后只能改出新用例 | `data/sets/<set>/cases.json` + `call{}`【方案 §四·测试用例】|
| 一次 | 再跑队列，或线上原本那一次 | 不可改 | SQLite 新表 `runs` |
| 检查结果 | 一次完成时自动跑格式 + 规则检查；AI 判官按 G-2 待定 | 检测器升版可重跑，旧结果留版本号 | SQLite `detections` |
| 人工判定 | 用户 | 用户随时改（覆盖，同今天）| SQLite `labels`，主键加 `run_id` |

### B-2 状态机

**线上真实记录**（不可逆，无删除）

```
[入库] ──(客户端带了 AI 判断名)──▶ 已认领 ──(用户按 c)──▶ 已存为测试用例（记录上挂用例链接，可挑多次）
   └──(没带)──▶ 没标明来源 ──(基本信息表补上映射规则 / 客户端改好后重跑)──▶ 已认领
```
- 记录带 `origin` 字段：`business`（线上业务）/ `judgebench-replay`（判官台再跑）。**再跑也经模型网关，也会进调用记录，但线上真实记录页默认只列 business**，否则再跑会把"线上真实"污染成自己跑自己。【方案 §四·调用记录"记下来的全是线上真实记录"要成立，就得把再跑分开】
- 失败记录（模型网关 5xx、超时、解析失败）也是记录，列表里排最前。线上失败本身是样本。【纪律·只收真跑样本】

**测试用例**

```
草稿 ──(锁定输入: 用户按"锁定"，或第一次再跑)──▶ 就绪 ──(≥1 次完成)──▶ 有跑 ──(用户归档)──▶ 归档
 │ 可改输入、可删                              │ 输入冻结                       │ 只读，不再排队
 └──(删除, 0 跑 0 判时直接删)                   └──(改输入 = 改出新用例，source=改坏的输入，parent=本用例)
```
- **输入冻结**：一个用例的 N 次要可比，输入不能中途变。要改就另生一个用例。【我提，见 G-2 第 4 条】
- 来源三种：线上真实记录 / 测试数据 / 改坏的输入，是用例出生时定的，之后不变。【方案 §四·测试用例；B7 拟真包要标明哪块补的】
- 归档不可逆，要确认（用例上已有人工判定和跑，删了一致率的分母就变）。删除只在 0 跑 0 判时允许，不要确认。

**一次**

```
排队 ──▶ 进行中 ──▶ 完成 ──(自动)──▶ 已检查(格式+规则)
                └──▶ 失败(网关错/超时)   ── 也进 N 次表，算"跑 N 次过几次"的分母
线上那次：从线上真实记录存为用例时，那次的模型回复直接成为 run=线上那次，状态=完成，且已带调用记录里自动检查的结果（二期）
```
- 一次完成后不可改；重跑检测器只加一行带版本号的检查结果，不覆盖。

**人工判定**（挂在一次上，不再挂在用例上）

```
未判 ──(p / f)──▶ 已判(通过|不通过) ──(再按同键)──▶ 未判   （同今天的切换逻辑）
逐条定位 findings 与一句批评随时增删改，350 ms 自动保存（同今天）
```
- AI 判官/检查结果**在人工判定存在之前不显示**——今天的"免得被带着走"。格式与规则检查是代码算的，要不要也藏？我的默认：格式检查不藏（解析都失败了不必假装看不见），规则检查与 AI 判官藏到判完。【判官台现状；我提，G-2 第 6 条】

**检查结果**：`未跑 / 通过 / 查出(n 条，逐条依据) / 检测器缺（该处自动检查未导出）/ 检测器异常（代码抛错）`。**"缺"和"异常"都不许显示成"通过"**。【纪律·拿不到就说没有】

**不可逆、要确认的动作清单**：归档用例；再跑（花钱，弹预计费用与次数）；把线上真实记录批量存为用例 ≥10 条时（提示会建多少用例）。其它要么可撤销，要么重复点也不会多出一份。

## C. 六条主流程

### ① 从线上真实记录存为测试用例

**入口**：AI 判断页 → "线上真实记录"，或总览行上的"线上 312"数字。

| 步 | 用户看到 | 用户做 | 系统回 |
|---|---|---|---|
| 1 | 记录列表（左栏）：时间、来源网关（服务器/本机）、状态点（✓ 成功 / ✗ 失败 / ⚠ 自动检查查出问题）、运行编号缩写（会话 `s-7f…` 轮 7 / 任务 `wf-…` / 册 `lighting` 重写 2）；默认按"失败与查出问题的优先，其次时间倒序" | 过滤条：网关来源、时间窗、只看失败、按运行编号搜 | 列表 + 右上 `12 / 312` |
| 2 | 记录详情（中栏）：**发给模型的内容**——固定那段系统提示词折叠一行（标"与基本信息表一致"或"⚠ 提示词与基本信息表登记的不同"），用户那句/图片展开，参数一行；**模型回复**——解析后的结构（JSON 树 / 图）为主，原文折叠；**自动检查**（二期）——各仓活动日志里同运行编号那行 | 读 | 右栏：基本信息两行 + 位置块（见 ⑥）+ 耗时/token/花费 |
| 3 | 右栏按钮 `c 存为测试用例` | 按 c | 弹小面板：**用例集**（默认 `<point>-线上-<当月>`，可选已有集或新建）、**一句为什么挑它**（可空）、**用例名**（系统从"为什么挑它"取网址名建议，如 `chat-intent-问句被当提供信息-0909`；拒纯数字名）、**跑几次**（默认 3，基本信息表可配每处默认） |
| 4 | 回车 | — | 用例建成：`source={kind:线上, record:<id>, gateway:服务器, at:…}`；发给模型的内容**复制一份存进用例**（不是链接——调用记录按天滚，链接会断）；那次的模型回复成为 `线上那次`，状态完成；页面跳到用例页，焦点在"再跑"按钮；提示"已存为测试用例，o 回记录" |
| 5 | 记录列表里这条多一个 `用例 ↗` 标记 | — | 同一记录可挑多次（比如同一记录要做不同改坏），但列表提示"已有 2 个用例" |

**批量**：列表里 `x` 勾选多条，`c` 一起存，同集同跑数，用例名 = 建议名 + 运行编号缩写。≥10 条弹确认。

依据：方案 §四·测试用例（线上真实记录来源）、§四·跑法（配跑次数）；B3 只收真跑（线上那次的回复就是真实跑出来的）；B13 只在服务器。

### ② 把用例的输入改坏

**入口**：用例页右栏 `d 改坏输入`（任何来源的用例都能改，父用例可以本身就是改坏的——链式）。

**改坏怎么表达**：**不发明表达式语法**——改坏就是"直接改这份输入"，系统记差异，不记规则。【红线：不发明表达式语法、不建通用平台】

| 步 | 用户看到 | 用户做 | 系统回 |
|---|---|---|---|
| 1 | 改坏页：中栏是父用例发给模型的内容，进入**可编辑态**（JSON 树可改值/删键/加项；对话历史可加轮；图片位置有"换图 / 处理"按钮）；顶部一排**快捷改法**：`抽掉字段` `塞禁用词` `历史加长到上限` `图片糊掉` `往用户话里塞指令` | 点一个快捷改法 | 快捷改法只是**替你做一次具体编辑**，改完停在编辑态让你看：<br>· 抽掉字段：弹出该处输入结构里的字段清单（来自基本信息表的结构定义），勾一个 → 删掉；<br>· 塞禁用词：从该处登记的禁用词表挑一个，插到你选中的字符串字段末尾；<br>· 历史加长：把最后一轮复制 k 次直到接近基本信息表写的历史上限（上限没登记 → 提示"该处没登记上限，填一个次数"）；<br>· 图片糊掉：对入图做高斯模糊/降采样，参数一个滑块，原图与糊图并排；<br>· 塞指令：在用户那句末尾追加一句你写的话，默认给一句示例但**光标停在那儿要你改**——不预置一句"标准攻击语" |
| 2 | 编辑后的差异高亮（删红 / 增绿，JSON 按路径，文本按字，图按缩略图并排） | 再手工调 | 右栏实时列"改了什么"：`ops[{name, path, before, after}]`——`name` 是快捷改法名或"手改"，是系统写的不是让你选分类 |
| 3 | 右栏：**一句为什么这样改**（必填，一句话，如"看它会不会照着塞进去的指令走"）、用例名建议 `<父名>-塞指令`、跑几次 | 填、回车 | 新用例建成：`source={kind:改坏的输入, parent:<父用例>, root_record:<最初那条线上真实记录>, ops:[…], why:"…"}`；父用例页多一条"改出 ↓ 1"；页面跳到新用例页 |

**来源怎么标、怎么挂钩**：
- 用例页顶部一条**来源链**：`线上 20260909-1140 → 改坏(塞指令) → 改坏(抽掉字段)`，每节可点回去。【B7/B8"mock 与真值在产出上分得开"】
- 判定页与一致率页对改坏输入的用例的每一次都带 `来源=改坏的输入` 徽章；一致率默认按来源分列，因为改坏集的不通过率天然高。
- 改坏输入的用例，模型回复是真实跑出来的，进样本；它的**输入**不是线上的，永远带标。**"预判它该怎么答"只写在 why 里，不当反例入库。**【B3；盘点 §B-补②；B21 正确答案只线下用】
- 测试数据用例（考卷/造的数据导入）同一套字段：`source={kind:测试数据, from:"reportgen/tests/fixtures/…", filled:["heights","household"]}`，`filled` 就是"哪块是补的"，来源链显示 `测试数据(补: 层高·业主情况)`。【B7 三条判断标准】

### ④ 对一次模型回复判"错没错"

三栏：左 = 本用例的各次列表（线上那次在最上，已判/未判点），中 = **上半判断依据、下半模型回复**，右 = 判定。**没有任何分类选择控件，整页找不到"类型"两个字。**【B15 + B18】

**通用部分**（三类 AI 判断一样）：

| 步 | 用户看到 | 用户做 | 系统回 |
|---|---|---|---|
| 1 | 中栏上半"判断依据"：这一次**输入里的事实**（该处基本信息表指定哪几块是判断依据：事实清单 / 特征固定清单 / 房间表 / 母版图 / 派活时给的文案）；系统提示词折叠 | 读 | — |
| 2 | 中栏下半"模型回复"：解析后的结构渲染（见 D） | 拖选一段 / 点一个条目 / 点图 | 右栏 findings 列表新增一条：`{location_kind, target, quote, note:""}`，光标自动落进 note 输入框 |
| 3 | 每条 finding 一个行内输入框，占位符"这处哪儿不对 / 应该是什么"（同今天） | 写一句 | 350 ms 保存 |
| 4 | 右栏 `[通过] [不通过]` 大按钮 | p / f | 存 verdict；**不通过且 findings 与批评都为空**时，按钮下出一行黄字"没写哪儿不对，归纳时这条用不上"，**不拦**（我提，G-2 第 3 条） |
| 5 | 判完后右栏下方展开：格式检查结果、规则检查查出的清单（每条带依据）、AI 判官结论（模型名、通过/不通过、依据、"与你一致/不一致"） | 看；若发现自己判错可改 | 改人工判定不清机器结果 |
| 6 | 底部"一句批评"总框（整次级，可空）——与逐条 note 并存：逐条说位置，总框说整体（"整段都在复读上一稿"） | 写 | — |
| 7 | `j` 下一次（同用例）；`u` 跳到本 AI 判断下一条未判（跨用例）| — | — |

**文本 JSON 回复怎么选段**：
- 模型回复渲染成带路径的树：每个叶子一行 `notes[1].text  "主卧朝南，冬天晒被子方便"`；列表型字段每项一个可点条目。
- **点条目** → finding `location_kind=element, target=json 路径 notes[1], quote=该项全文`。
- **拖选字符** → `location_kind=span, target=json 路径 notes[1].text, offset=[8,14], quote="冬天晒被子"`。存的是**原文片段 + 路径**，不是行号（重排不失效）。【B6 打回三件：原文片段 + 哪儿不对 + 怎么改】
- 与 B16"被验产物不当坐标系"不冲突：这里引用的是模型回复本身的片段，就是被打回的对象；B16 禁的是拿模型认的房间名去定位**图上**的位置。
- `n` 进入选段模式（同今天图侧的"在图上点位置"），`esc` 退出；`0` = 整条（whole）。

**对话怎么按轮**：
- 一次 = 一轮模型回答（`chat-orchestrate` 的 `{facts[], replies[]}`）。中栏上半是**历史**（气泡，默认只展开最后两轮，更早折叠成"…前 9 轮"），最下一条业主气泡高亮"本轮输入"；下半是本次产物：**抽出的事实**逐条（可点）+ **回复句**逐句气泡（可点、可选段）。
- 判定对象只有本次那一轮；历史不能判（它是输入）。历史里某轮若是从调用记录挑的线上真实内容，气泡角标 `线上`；改坏加长的轮角标 `改坏`。
- `chat-intent` 更简单：模型回复只有一个选项值，条目就一个；中栏上半是那句业主的话，右栏 findings 通常只有"整条"。

**图怎么点位置**：同今天——`n` 进点图模式，点一下记的是按比例算的坐标（0 到 1，不是像素），`0` 整张。加一样：**看图类**（图进、JSON 出）的模型回复是框/名字，把框叠画在入图上，**点框** → `element, target=rooms[3]`（引用回复条目），**点框外空白** → point（漏画退回坐标点，同 store.py 注释里的规则）。【store.py `_norm_findings`；B16】

## D. 三类 AI 判断在看输入输出与判定时的差异

三种检查 = 格式检查 / 规则检查 / 人工判定。【方案 §四·应该满足什么】

| | 文本 JSON 输出 | 看图类（图进、JSON 出） | 生图类 |
|---|---|---|---|
| 哪些处 | chat-intent、chat-orchestrate、floorplan-notes、floorplan-copy、report-derive、report-compose、report-judge | floorplan-survey、floorplan-region、floorplan-verdict | atmosphere-visual、realism-pass |

## E. 效率设计

一个人每天几十上百条，目标：**手不离键盘、每条不超过三次点击、随时知道还剩多少**。

**键盘流**（全局，输入框聚焦时不吃键，同今天）

| 键 | 作用 | 备注 |
|---|---|---|
| `j` / `k`、`→` / `←` | 下一条 / 上一条（同级：记录 / 用例 / 次） | 到底不绕回，提示"已是最后一条，u 跳未判" |
| `u` | 本 AI 判断下一条未判的次 | 跨用例；总览上 `u` = 未判最多的 AI 判断 |
| `p` / `f` | 通过 / 不通过（再按取消） | 同今天 |
| `n` | 记一条：文本进选段模式，图进点图模式 | `esc` 退出 |
| `0` | 整条 / 整张 | — |
| `1`–`9` | 焦点跳到第 n 条 finding 的 note 框 | — |
| `c` | 存为测试用例（记录页） | — |
| `d` | 改坏输入（用例页） | — |
| `r` | 再跑（用例页） | — |
| `x` | 勾选（列表多选） | `shift+x` 区间 |
| `o` | 回到来源（用例 → 记录；改坏的 → 父用例） | — |
| `g` 然后 `p` / `l` / `a` | 去 AI 判断页 / 线上真实记录 / 一致率 | 两键序列 |
| `/` | 焦点到过滤框 | — |
| `?` | 显示这张表 | — |

**批量**：记录列表勾选 → 一起存为测试用例；用例列表勾选 → 一起再跑（N 各用自己的默认）；一致率页某格 → 那几次逐条过（`j` 只在这几条里走）；"跑 AI 判官：还没判的 N 条"按钮照旧。

**计数**：顶栏常驻 `未判 N`（当前 AI 判断）；总览每行"未判次"；左栏列表每个用例后 `3/5 已判`；今天的进度条（通过/不通过两色）保留在用例页头。

**默认折叠**：系统提示词（固定那段，与登记一致时）；对话历史早于最后两轮；发给模型的内容的原始 JSON；基本信息除两行外；`hidden` 执行者记录（同今天"先判完再看"）；机器结果（人工判定前）；N 次表里失败次的原始错误正文；改坏差异（用例页头只露 ops 一行，点开看 diff）。

**记忆**：每处 AI 判断最后停留的条目存 localStorage，回来续判；过滤条件进 URL query，可以发给另一个 session。

**加载**：记录列表分页 50 条，滚到底加载；图懒加载；判定页预取下一条。

| 某处 7 天 0 记录 | 行灰字"7 天无调用"——线上没跑过这条线，不是坏 |
| 有没标明来源的记录 | 总览顶部黄条"没标明来源 12 条（模型名 floorplan-parse.default ×12）：客户端没带 AI 判断名，改 aipipe worker 的 llm_client 加一个参数" |
| 某处自动检查未导出 | 用例页/一致率页规则检查列写"该处自动检查未导出（reportgen run_unit_gate 未接）"，**不显示通过** |
| 某处无 AI 判官 | 一致率页 AI 判官行"该处无 AI 判官"；判定页不出 AI 判官框 |
| 用例 0 跑 | N 次表空，中间一个 `r 再跑`；线上那次存在时至少 1 行 |
| 一致率 n=0 | "两边都判过的 0 条。先判几次（u），检测器结果自动就有。" |
| 基本信息表里有但模型网关没这个模型名 / 反之 | 总览底部一行列出，链到 infra 配置路径 |

**错误态**

| 场景 | 处理 |
|---|---|
| 再跑时模型网关 5xx / 超时 | 那一次状态"失败"，原文照实显示，进分母；不重试（要重试用户再按 r）|
| 检测器抛错 | 结果"检测器异常" + traceback 折叠；不算查出也不算通过 |
| AI 判官解析失败 | verdict 空、raw 保留（同今天 judge.py）|
| 调用记录的图片文件丢了（按天滚掉） | 记录页显示"入图已滚出调用记录（保留 N 天）"，此记录不能再存为用例；已存的用例不受影响（自带副本）|
| 基本信息表 sha 与调用记录的 code_rev 不同 | 黄字提示，不拦 |
| 费用估不出 | 显示"— 单价未配"，再跑确认条照出，不填猜的数 |

**并发**（同一集另一个 session 在改——用户手记里已发生过 `git add -A` 互相带走）

- 人工判定每条带 `at`；PUT 时前端把上次看到的 `at` 一起送，服务端不一致返回 409；页面右栏顶部出黄条"这次在 12:03 被另一处改过：[看那边的] [用我的覆盖]"，不自动合并，不静默覆盖。
- `cases.json` 服务端记 mtime；用例页加载时带 etag，写（新建/改坏/归档）时不一致返回 409，提示"用例集在你打开之后被改过，刷新再做"。存用例/改坏是**追加**操作，服务端追加而不是整文件回写，两个 session 各追加不会互相丢。
- 再跑队列在服务端，两个 session 对同一用例同时按 r 就是两批，各自编号，N 次表都显示；不合并。
- 顶栏"最近 5 分钟另一处写过本集"的小提示（读 labels/runs 最新 at 与自己 session id 比），只提示不锁。
- 判官台单进程 SQLite WAL（今天就是），写冲突靠上面的版本比对，不上锁。

# 第二节 · 视觉设计说明

稿子 `judgebench-visual.html`，顶部 tab 切五页，右上是通过率显示开关与主题开关。

## 设计原则
一个人每天对着大量文本与图判"错没错"，优先三件事：**模型回复本身最大最亮**，其余一切退成灰字；**结果只用三种符号**（✓ 过 / ✕ 不过 / — 没跑或没有检测器），不靠色块面积；**同一个动作跨三种载体**——图上点一处、正文拖选一段、对话选一轮，都是"指到哪儿，写一句问题"。

## 色彩与层级
沿用现有页的颜色（青主色、绿过、红不过、琥珀提醒、紫 AI 判官），新增来源三色、选区黄、代码底。层级靠留白与字号，不做大面积填色；总览卡左缘一条色线区分模型类型（灰＝文本、紫＝看图、橙＝生图）。

## 三种来源
真实＝实心青底 ●；测试＝蓝色虚线框 ◌；改坏＝橙色斜纹底 ✂，并强制带"改了什么"一行。形状、边框、底纹三样都不同，色盲与深色下也分得开。

## 三种检查的结果
格式检查 / 规则检查 / 人工判定各一列，表头写全称，不用颜色区分列。格式检查是单个 ✓✕；规则检查是"抓到 n 条"加规则名（中文 + 代码名小字）；人工判定是"错 / 没错 / 未标"加一句问题。格式检查没过的那次，后两项灰掉。汇总只写"跑 5 次过 3 次"。多次回复横向并排，与第 1 次不同的行标黄。

## 通过率（要不要显示待你决定）
通过率、一致率这类汇总数按 9-04 你定的不上页。每张卡底部预留一块，默认不渲染，顶栏开关打开才出现并带"待你决定"标。要上删一行 CSS，不上永远不出现。

## 深色模式
跟随系统与手动切换各一套变量，与现有页同源；图不随主题变。

## 与现有页的延续与改动
延续：三栏、判完才显示 AI 判官、P/F 快捷键、图上点位、标出的问题列表。改动：主体从"一张图"扩成"发给模型的内容 / 模型回复"对照（文本＝消息与 JSON，看图＝入图加框叠回原图，生图＝线稿对结果图）；左栏改成"最近的真实记录"，测试用例另成一页；右栏加"存为测试用例 / 把输入改坏 / 再跑 N 次"；判定按钮改成"没错 / 错"。

## 拿不准、要你定
1. 判定按钮用"没错 / 错"还是"通过 / 不通过"。
2. 总览卡上"已知问题"要不要长期放。
3. 文本选区存"卡片 id + 字符位置"，重跑后失效，问题是否只挂在那一次上。
4. 对话以轮为最小单位、不做字级选区，够不够用。
5. 再跑失败那次"不算过也不算不过"，还是算不过。
6. 用词保留了几个拿不准的：**考卷**（现成的一套测试输入）、**母版 / 线稿**（你在用的图名）、**保真度**（生成图与线稿的相似分数）、规则抓到问题时显示的代码名（如 `cites-missing`，页面上会配一句中文）、提示词原文里的"缺口""几何"（是真实发给模型的内容）。

## 问号说明
**放在哪**：共 104 枚问号 + 顶栏一个"第一次用？"。总览页：每张卡右上角、三个数的标签旁、每条"已知问题"、通过率开关；详情页：最近的真实记录、发给模型的内容、模型回复、自动检查、存为测试用例、再跑 N 次、把输入改坏、基本信息；用例页：来源三种标记、应该满足什么、结果表表头、多次回复并排；标注页：你的判定、标出的问题、整条一句话、AI 判官、判断依据；空态页六块标题各一个。同一功能在不同页出现，共用同一条文案，一共 34 条。

**文案原则**：每条三段——这是什么 / 怎么用 / 什么时候用它，每段一两句；只用已经换好的白话；出现代码名时紧跟一句解释（如 len>24 是"超过 24 字"）；"什么时候用它"写的是判断动作里的时机，不写功能定义。"第一次用？"五句：工具是干什么的、记录从哪来、人只做一件事、结果怎么看、通过率为什么默认藏。

**交互**：灰色小圆圈，悬停或打开时变主色；卡片里的问号默认半透明，鼠标进卡才实。点开就地弹出，再点、点外面、按 Esc、点 × 都能关，同时只开一个；键盘可达，带 aria-label 与 aria-expanded；宽 320px，窄屏自动缩到屏宽以内并向上翻。

**拿不准**：一是总览页每张卡三个数都放了问号，共 36 枚，虽已做成半透明，还是可能显多，可改为只在图例处放一个；二是"第一次用？"要不要在第一次打开页面时自动弹一次；三是问号点开后要不要记住"看过了"（看过的变更淡）。
